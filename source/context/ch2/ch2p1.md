#	LoongArch指令特性

龙芯基础指令集LoongArch是RISC风格的指令系统架构，具有RISC指令架构的典型特征。RISC的核心思想是简化：指令功能相对简单，CPU执行单条指令所需周期较短；抛弃变长指令编码格式，统一采用定长指令，使CPU译码过程更简单，符合“常用的做得快、少用的只要对”的原则；采用Load-Store结构，只有访存指令能够访问内存，其他指令的操作对象均为寄存器或立即数。精简设计不仅有利于硬件高效实现，也有利于通过流水线、多发射、乱序执行等技术提升效率。这些优势也使非RISC架构的代表x86架构不断趋向RISC风格，即将较复杂的指令预译码为多个简单操作，以便更有效地使用流水线等技术。典型RISC指令系统架构还包括MIPS、ARM、SPARC、PowerPC、RISC-V等。

本节将从指令组成与分类、寄存器、指令长度和编码格式等方面介绍龙芯基础指令集LoongArch。

##	指令组成和指令分类

第01章提到，计算机语言也有一套标准语法规范，计算机正是依据这些规范理解用户意图并执行相应操作。计算机能够识别的语言是机器语言，其最小识别单位是指令。那么，机器指令的语法规范是什么？一般来说，一条指令包含操作码和操作数。操作码定义指令功能，例如加法、减法等；操作数定义完成指定功能所需的对象，例如寄存器、常数、地址等。下面给出3条功能不同的龙芯汇编指令：
``` asm
or 		$r4, $r0, $r0		#	r4 = r0|r0
addi.d	$r3, $r3, 16(0x10)	#	r3 = r3 + 16
jirl	$r0, $r1, 0 		#	jump to address(r1 + 0)
```
这里`or`、`addi.d`和`jirl`都是操作码，分别表示或运算、加法运算和跳转。其中，加法指令`addi.d $r3,$r3,16(0x10)`中的`i`代表立即数（Immediate），表示当前指令中有一个操作数是常数；`.d`表示当前加法指令的操作数是64位数据类型。

操作码后面的内容均为操作数。例如，上述或运算指令`or $r4,$r0,$r0`中的操作数为寄存器r4和寄存器r0，其功能是对寄存器r0的值进行或运算，并将结果写入寄存器r4。上述加法指令中，操作数分别是寄存器r3和立即数16。

龙芯基础指令集包含约300条指令，按功能可分为运算指令、访存指令、转移指令和特殊指令四大类。运算指令用于实现加、减、乘、除、移位、逻辑与、逻辑或、逻辑非等运算功能，上述示例中的`or`、`addi.d`属于运算指令。访存指令用于实现处理器从内存读取数据到寄存器，或从寄存器写入数据到内存。转移指令用于控制程序执行流向，在机制上类似C语言中的`if-else`、`switch`、`goto`等语句，上述示例中的跳转指令`jirl`属于转移指令。特殊指令用于操作系统相关的特殊用途，例如系统调用、获取处理器特性、触发断点例外等。本书第03章将按照功能分类详细介绍龙芯基础指令集。

##	寄存器

寄存器是处理器中最常用的存储单元。LoongArch中大多数指令的操作数为寄存器或立即数。现代指令系统通常定义一定数量的通用寄存器和浮点寄存器，供编译器进行充分的指令调度。龙芯指令系统定义了32个整数通用寄存器（General-purpose Register，GR）和32个浮点寄存器（Floating-point Register，FR），编号分别表示为$r0~$r31和$f0~$f31，如图2-1和图2-2所示。

```{image} ../../img/ch2/pic_2_1.png
:alt: 整数通用寄存器
:class: bg-primary
:scale: 50 %
:align: center
```

从图2-1可以看出，LA32架构下通用寄存器位宽为32位，LA64架构下通用寄存器位宽为64位。从指令集角度看，可以将LA32视为LA64的子集。以加法指令为例，LA32架构下仅有32位加法指令，而LA64架构下既有32位加法指令，也有64位加法指令。如下两条指令分别实现64位整数加法和32位整数加法。
``` asm
add.d 	$r8, $r1, $r2	#	64位加法运算指令，仅适用于LA64
add.w 	$r8, $r1, $r2	#	32位加法运算指令，在LA32和LA64架构下都适用
```
在LA64架构下执行32位加法指令`add.w r8, r1, r2`时，虽然寄存器r1、r2和r8均为64位，但CPU只取寄存器r1和r2的低32位参与运算，再将运算结果的低32位符号扩展为64位后写入寄存器r8。对于`add.d r8, r1, r2`，参与运算的是寄存器r1和r2的完整64位，结果直接写回寄存器r8。

```{image} ../../img/ch2/pic_2_2.png
:alt: 浮点寄存器
:class: bg-primary
:scale: 50 %
:align: center
```

从图2-2可以看出，浮点寄存器与整数通用寄存器不同。无论在LA32架构还是LA64架构下，浮点寄存器的位宽均为64位。仅当指令操作单精度浮点数或字整数（32位整型）时，数据只存放在浮点寄存器的[31:0]位，浮点寄存器的[63:32]位为无效值。在龙芯基础指令集中，可以从浮点数指令名中明确区分数据类型。例如下面两条浮点数加法指令，指令名中的`.s`表示单精度浮点数加法指令，`.d`表示双精度浮点数加法指令。
``` asm
fadd.s 	$f3, $f1, $f2 	#	单精度浮点数(32位)的加法运算 f3[31:0] = f1[31:0] + f2[31:0]
fadd.d 	$f3, $f1, $f2 	#	双精度浮点数(64位)的加法运算 f3 = f1 + f2
```
与浮点数指令编程相关的还有两类寄存器：条件标志寄存器（Condition Flag Register，CFR）和浮点控制状态寄存器（Floating-point Control and Status Register，FCSR），分别用于存放浮点比较结果，以及浮点运算中的非法操作、除零、溢出等异常状态。第04章将详细介绍这两类寄存器的使用。

##	指令长度和编码格式

RISC指令架构的典型特征之一是指令定长。龙芯基础指令集中，每条指令的编码长度固定为32位。指令编码指操作码和操作数在32位指令中的排列方式和占位比例。图2-3列举了龙芯架构9种典型编码格式。

```{image} ../../img/ch2/pic_2_3.png
:alt: 龙芯架构典型指令编码格式
:class: bg-primary
:scale: 50 %
:align: center
```

从图2-3可以看出，龙芯架构的指令编码风格是操作码（opcode）位于高位，目的操作数（rd）位于低位，其他源操作数或立即数位于中间位置。不同编码格式中，操作码所占位数不同。例如，两个操作数（2R-type）编码格式使用22位表示操作码，三个操作数（3R-type）编码格式使用17位表示操作码。寄存器均占用5位进行编码（图2-3中的ra、rk、rj）。常数占位分别有12位（I12）、14位（I14）、16位（I16）、21位（I21）和26位（I26）。

需要指出的是，图2-3并未列出龙芯架构的全部编码格式。少数指令的编码格式与这9种典型编码格式不同，但这类指令数量不多，变化幅度也不大，不会给开发人员带来明显不便。例如，部分指令仅有1个操作数，如系统调用指令`syscall code`、中断指令`break code`等。在应用级基础整数指令中，非三操作数指令总数不到10条。龙芯指令集中大部分指令为3个操作数（如3R-type、2RI8-type、2RI12-type等），极少数指令为2个操作数（2R-type、I26-type）或4个操作数（4R-type）。

每条指令都有唯一的操作码值。图2-4列举了龙芯基础指令集中部分指令的操作码值及指令编码规则，其他指令对应的码值可查阅龙芯架构参考手册末尾的指令码表。

```{image} ../../img/ch2/pic_2_4.png
:alt: 龙芯指令集中部分指令码
:class: bg-primary
:scale: 50 %
:align: center
```

以图2-4中的指令ADDI.D为例，其操作码固定为0b0000001011。对汇编指令`addi.d $r3,$r3,-16(0xff0)`进行机器指令编码，得到的二进制结果为
``` c

```
这个二进制结果对应的十六进制为0x02c04063。

##	指令汇编助记格式

良好的指令汇编助记格式有助于开发人员理解汇编语言含义并提高开发效率。龙芯指令汇编助记格式主要包括指令名和操作数两部分。

指令名由“指令名前缀+指令名+指令名后缀”3部分组成，通过指令名前缀区分向量指令、整数指令和浮点数指令。具体来说，128位向量指令的指令名以字母“V”开头，256位向量指令的指令名以字母“XV”开头，浮点数指令以“F”开头，其余没有特殊标识的为普通整数指令。指令名的定义与其他架构指令集类似，通常采用能够表达指令功能的英文单词或缩写，例如`add`表示加法指令，`sub`表示减法指令。指令名后缀用于区分指令操作对象的类型。对于整数类型操作数，指令名后缀包括`.B`、`.H`、`.W`、`.D`、`.BU`、`.HU`、`.WU`、`.DU`，分别表示字节、半字、字、双字、无符号字节、无符号半字、无符号字、无符号双字；对于浮点数类型操作数，指令名后缀包括`.S`、`.D`，分别表示单精度浮点数和双精度浮点数。

寄存器操作数的助记格式较为简单：以`rN`标记通用寄存器，以`fN`标记浮点寄存器，以`vN`标记向量寄存器，以`xN`标记扩展向量寄存器。其中，N为数字，表示操作第N+1号寄存器。LoongArch的通用寄存器、浮点寄存器、向量寄存器各有32个，因此寄存器操作数分别可表示为r0~r31、f0~f31、v0~v31、x0~x31。例如，r3代表整数通用寄存器集中的第4号寄存器。

掌握规范的指令汇编助记格式后，读者可以较容易地理解下面几条汇编指令的含义。
``` asm
add.w 	$r8, $r1, $r2 	#	32位整数加法运算
fadd.s 	$f8, $f1, $f2 	#	单精度浮点数加法运算
vadd.b 	$v8, $v1, $v2	#	128位向量整数加法运算，数据类型为字节
xvadd.b $x8, $x1, $x2	#	256位向量整数加法运算，数据类型为字节
```
在龙芯自主指令集LoongArch中，包含立即数的指令通常采用“指令名+i”的命名格式。例如下面的指令：
``` asm
addi.w 	$r8, $r1, 16 	#	32位整数加法运算
```
:::{tip}
龙芯自主指令集LoongArch不区分指令名大小写，即`add.w`和`ADD.W`都是合法且可被识别的写法。不过，建议统一使用小写。
:::

##	符号扩展

在龙芯指令集中，所有计算指令中的立即数都需要先进行符号扩展或无符号扩展（也称零扩展），然后再参与计算。扩展方式包括32位符号扩展、32位无符号扩展、64位符号扩展和64位无符号扩展。32位符号扩展是将n位（n小于32）立即数的高32-n位填充为立即数最高位；32位无符号扩展是将n位立即数的高32-n位填充为0。64位符号扩展是将n位（n小于64）立即数的高64-n位填充为立即数最高位；64位无符号扩展是将n位立即数的高64-n位填充为0。在LA32架构下，通常将立即数扩展为32位。在LA64架构下，通常将n位立即数扩展为32位或64位。表2-1列举了两个16位立即数0x8000和0x1000分别符号扩展、零扩展至32位和64位的结果。

:::{list-table} 
:widths: 40 30 30
:header-rows: 0

*	-	16位立即数
	-	0x8000
	-	0x1000
*	-	符号扩展至32位
	-	0xFFFF8000
	-	0x00001000
*	-	零扩展至32位
	-	0x00008000
	-	0x00001000
*	-	符号扩展至64位
	-	0xFFFFFFFFFFFF8000
	-	0x0000000000001000
*	-	零扩展至64位
	-	0x0000000000008000
	-	0x0000000000001000
:::

例如，龙芯基础指令集中的32位加法指令`addi.w rd, rj, si12`，需要将立即数si12（12位有符号立即数）符号扩展到32位后，再与rj进行加法计算。64位加法指令`addi.d rd, rj, si12`，需要将立即数si12符号扩展到64位后，再与rj进行加法计算。逻辑与运算指令`andi rd, rj, ui12`在LA32架构下将立即数ui12（12位无符号立即数）零扩展至32位后再进行逻辑与运算；在LA64架构下则将立即数ui12零扩展至64位后再进行逻辑与运算。

在LA64架构下的32位操作数计算指令中，计算结果通常也需要先进行64位符号扩展，再写入目的寄存器。例如，在LA64架构下执行32位加法指令`addi.w rd, rj, si12`时，运算过程是先将立即数si12符号扩展至32位，再与寄存器rj的低32位进行加法运算，最后将运算结果的低32位符号扩展至64位并写入目的寄存器rd。

##	寻址方式

寻址方式指如何使用指令中的操作数表示指令要访问的地址。根据指令中操作数的不同格式，LoongArch指令系统支持5种寻址方式：寄存器寻址、立即数寻址、基址+立即数偏移寻址、基址+寄存器偏移寻址和相对寻址。其格式和含义如表2-2所示，其中符号`#`表示立即数，数组`regs[]`表示寄存器，数组`mem[]`表示存储器。

:::{list-table} 
:widths: 30 30 50
:header-rows: 1

*	-	寻址方式
	-	指令示例
	-	格式说明
*	-	寄存器寻址
	-	ADD R1,R1,R2
	-	regs[R1] = regs[R1] + regs[R2]
*	-	立即数寻址
	-	ADD R1,R1,#2
	-	regs[R1] = regs[R1] + 2
*	-	基址 + 立即数偏移寻址
	-	LD 	R1,R2,#100
	-	regs[R1] = mem[regs[R2] + 100]
*	-	基址 + 寄存器偏移寻址
	-	LD 	R1,R2,R3
	-	regs[R1] = mem[regs[R2] + regs[R3]]
*	-	相对寻址
	-	BL 	#100
	-	pc = PC + 100
:::

寄存器寻址是指操作数位于寄存器中。格式`ADD R1,R1,R2`表示将寄存器R1中的值与寄存器R2中的值进行加法运算，并将结果写回寄存器R1。寄存器寻址方式广泛用于LoongArch指令集中的各类指令，例如算术运算指令（加法、减法、乘法、除法）、逻辑运算指令、移位运算指令、位操作指令等。

立即数寻址是指操作数本身直接在指令中给出，处理器取出指令时也就取得了操作数。格式`ADD R1,R1,#2`表示将寄存器R1中的值与立即数2进行加法运算，并将结果写回寄存器R1。在LoongArch指令集中，加法指令，逻辑运算中的与、或、异或指令，以及移位运算中的左移、右移等指令，都支持立即数寻址方式。由于指令长度固定（LoongArch中指令长度为32位），指令中可表示的立即数大小（或长度）会受到限制，通常为12位。

基址+立即数偏移寻址是指令中的寄存器存放操作数地址基址（可表示为base_reg），指令中的立即数存放操作数地址偏移（可表示为offset_imm），最终要访问的操作数所在内存地址为基址与立即数偏移之和（base_reg+offset_imm）。指令示例`LD R1,R2,#100`表示从指定内存地址读取一个数据到寄存器R1中，该内存地址的计算方式为R2与立即数100相加。

基址+寄存器偏移寻址是指操作数地址基址（可表示为base_reg）和地址偏移（可表示为offset_reg）分别存放在两个寄存器中，最终要访问的操作数所在内存地址为基址与寄存器偏移之和（base_reg+offset_reg）。指令示例`LD R1,R2,R3`表示从指定内存地址读取一个数据到寄存器R1中，该内存地址的计算方式为寄存器R2与寄存器R3相加。LoongArch指令集中的访存指令包含基址+立即数偏移寻址和基址+寄存器偏移寻址方式。

相对寻址与基址+立即数偏移寻址方式类似，区别在于相对寻址以程序计数器PC的当前值为基址，以指令中的立即数为偏移量，两者相加后得到操作数的有效地址。指令示例`BL #100`表示跳转到一个指定地址，该地址的计算方式为PC+100。相对寻址用于LoongArch指令集中的分支指令以及有条件/无条件跳转指令。
