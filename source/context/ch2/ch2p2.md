#	C语言到LoongArch的编译过程

GCC原名为GNU C语言编译器（GNU C Compiler），最初的功能是将C语言源程序翻译为特定架构处理器可识别和执行的目标文件（其中包含特定架构的机器指令）。随着程序设计语言不断发展，GCC除支持C语言外，也逐步支持C++、Objective-C、Fortran、Java、Ada、Go等语言，其名称也改为GNU编译器套件（GNU Compiler Collection）。不同语言的编译原理和流程具有一定相似性，基本流程通常包括词法分析、语法分析、语义分析、中间代码生成、汇编指令生成、目标机器指令生成、链接等阶段。目前，GCC编译器支持x86、ARM、PowerPC、RISC-V、s390、MIPS、LoongArch等主流架构。如果读者使用的是基于龙芯5000系列处理器的计算机，系统通常内置GCC编译器；如果使用的是非龙芯架构计算机，则需要从龙芯官网自行下载LoongArch架构的GCC交叉编译器。

了解GCC编译的基本流程，有助于加深对高级语言向机器指令转换过程的理解。下面通过编译一个C语言示例，介绍GCC在龙芯平台下的工作流程。

首先编写一个简单的C语言程序，其功能是向终端输出一句话。文件名为`hello.c`，内容如下：
``` c
/*this is test file*/
#include <stdio.h>
#define STR "Hello World!"

int main(){
	printf("%s\n", STR);
	return 0;
}
```
程序编写完成后，通过GCC工具编译文件`hello.c`，执行命令如下：
``` shell
$ gcc  -v --save-temps hello.c -o hello
gcc 版本 4.9.4 20160726 (Red Hat 4.9.4-14) (GCC)
cc1 -E -quiet -v hello.c -o hello.i
cc1 -fpreprocessed hello.i  -o hello.s
as -v -EL-o hello.o hello.s
collect2  -o hello  crt1.o crti.o crtbegin.o hello.o crtend.o crtn.o
```
:::{tip}
为了便于后续分析，这里对输出信息做了删减和整理。
:::
`gcc`命令的基本格式如下：
``` shell
gcc [options] file...
```
可以通过最简单的命令`gcc hello.c`，将`hello.c`中的C语言程序翻译成默认名为`a.out`的目标文件。为了查看编译基本过程及其产生的中间文件，本示例增加了额外参数，具体如下。

-	`-v`：显示编译器的具体编译过程。
- 	`--save-temps`：不删除中间文件，即保留编译过程生成的临时中间文件。本示例命令完成后，会在当前目录下产生`hello.i`、`hello.s`、`hello.o`这3个中间文件。
-	`-o <file>`：指定最终生成的目标文件名称；不指定此参数时，目标文件名称默认为`a.out`。例如，`-o hello`表示指定最终文件名称为`hello`。

从上面的输出信息可以清晰看出，GCC编译过程中涉及3个工具：`cc1`、`as`和`collect2`。`cc1`是第01章提到的编译器，负责对高级语言源文件（如`hello.c`）进行预处理，产生第一个中间文件`hello.i`；随后，`cc1`再对预处理文件进行翻译，生成汇编源文件`hello.s`。`as`是汇编器，负责对汇编源文件进行翻译处理，生成包含机器指令的目标文件`hello.o`。`collect2`是链接器，负责将多个目标文件（`*.o`）组合生成最终可在特定指令架构计算机上运行的目标文件`hello`。图2-5直观描述了这一过程。

##	预处理和编译阶段

编译的目的是将C语言源程序转换为与计算机体系架构相关的汇编语言，使用的工具是`cc1`，其内部可分为预处理和编译两个阶段。

预处理阶段主要处理各种预处理命令（例如源文件`hello.c`中以`#`开头的语句），包括头文件包含、宏定义扩展、条件编译选择等，最终产生供下一阶段使用的`.i`文件。预处理的主要规则如下。

(1) 处理所有以`#`开头的语句。例如，遇到`#if`、`#else`、`#endif`等宏判断语句后，保留条件成立的部分并删除其他部分；遇到`#define`宏定义语句后，对其后内容进行扩展，然后删除`#define`语句。因此，在`hello.i`中已经看不到源文件`hello.c`中的宏定义`STR`，它已被扩展到使用位置，故`printf`语句由如下形式：
``` c
printf("%s\n", STR);
```
扩展为如下语句：
``` c
printf("%s\n", "Hello World!");
```
遇到`\#include`语句后，预处理器会将被包含文件的详细位置信息插入当前位置，然后删除该语句。例如，示例中的`\#include <stdio.h>`被扩展为：
``` c
"/usr/include/stdio.h"
```
(2) 删除源文件中的所有注释（用符号`//`或`/*...*/`标注的内容）。例如，`hello.i`中已经看不到`hello.c`中的注释信息`/*this is test file*/`。

(3) 为调试添加行号和文件名标识。例如，在文件`hello.i`中会看到类似`# 1 "/usr/include/stdio.h" 1 3 4`的内容，用于在编译阶段生成调试所需的行号信息，并在产生错误或警告时显示行号。

编译阶段以预处理后的文件`hello.i`作为输入，再次使用`cc1`工具生成包含汇编代码的汇编源文件`hello.s`。该阶段主要对`hello.i`中的内容进行语法分析、语义分析和汇编代码生成。语法分析的主要任务是检查源程序是否符合程序设计语言的语法规则，例如括号是否匹配、语句是否以`;`结束等；语义分析的主要任务是类型检查，即确认每个运算符使用是否恰当，例如数组索引是否为非法小数、函数调用时参数类型是否不匹配、局部变量是否重复定义等；汇编代码生成则是将语法分析和语义分析后产生的中间表示，翻译为与计算机体系架构相关的汇编代码，并输出到`.s`文件。

代码优化也是贯穿编译阶段的重要功能。常见优化手段包括方法内联（Inlining）、循环展开（Unrolling）、死代码消除（Dead Code Elimination）等。GCC编译器提供`-O0`（默认）、`-O1`、`-O2`、`-O3`等优化选项，数字越大，代码优化程度越高，但编译时间通常也越长。

:::{note}
方法内联是指编译器在编译过程中，将被调用方法的代码副本放置到每个调用位置，以降低方法调用产生的性能开销。
:::
:::{note}
循环展开是指编译器在编译过程中多次复制循环体内部指令，使循环次数减少或被消除，以降低循环分支指令带来的性能开销。
:::
:::{note}
死代码消除是指编译器在编译过程中识别并删除那些永远不会被执行的代码。
:::

如果仅想查看源文件对应生成的汇编文件内容，也可以在编译时使用参数`-S`，例如下面两条命令都可以使用。
``` shell
$ gcc -S hello.c
$ gcc -S hello.c -o hello.s
```
由于`hello.s`是普通文本文件，因此可以使用文本工具直接打开并查看其内容。生成的`hello.s`文件内容大致如下：
``` asm
.LC0:
.ascii 	"Hello World!\000"
.LC1:
.ascii 	"%s \n\000"
main:
	addi.d 		$r3, $r3, -16
	la.local 	$r5, .LC0
	la.local	$r4, .LC1
	bl 		%plt(printf)
	or 		$r4, $r0, $r0
	addi.d 		$r3, $r3, 16
	jr 		$r1
```
其中，`.LC0:`、`.LC1:`、`main:`都称为标签，可用于标识字符串区域起始位置或函数入口地址。

`main:`标签后面共有7条汇编指令，是对源文件`hello.c`中`main`函数的等价实现。其中，指令`addi.d $r3,$r3,-16`和`addi.d $r3,$r3,16`用于栈空间的申请和释放；指令`la.local $r5,.LC0`和`la.local $r4,.LC1`分别用于加载函数`printf`所需的两个参数；指令`bl %plt(printf)`实现对`printf`函数的调用；指令`or $r4,$r0,$r0`和`jr $r1`分别用于加载`main`函数返回值0和执行函数返回。

:::{tip}
在龙芯架构中，寄存器r3被定义为栈指针（Stack Pointer，SP）；用于函数参数传递的寄存器是r4~r11，同时寄存器r4也用作函数返回值寄存器。更详细的指令讲解和寄存器使用规则请阅读第03章和第05章。
:::

:::{tip}
指令`la.local`是汇编宏指令，并不是龙芯指令集中的真实指令，不能被CPU直接识别和运行，只能被汇编器识别。这里的宏指令是龙芯架构为方便开发人员快速编写龙芯汇编程序而提供的，会被GCC汇编器识别并转换为相应的真实汇编指令。其他架构也存在类似的宏指令。
:::

##	机器指令生成阶段

机器指令生成阶段使用的工具称为汇编器（`as`），其主要任务是解析汇编源文件`hello.s`，并将其中的汇编语句按照指令码表编码为处理器可识别的机器指令，生成目标文件`hello.o`。

目标文件（以`hello.o`为例）不是文本文件，其中内容不能直接被人类阅读。如果要正确查看文件的具体内容，可以借助反汇编工具`objdump`。`objdump`工具用于将目标文件转换为人类可读的文本形式，命令格式为
``` shell
$objdump <option> <objfile>
```
`option`可以是`-f`、`-h`、`-d`、`-t`等参数，分别用于显示目标文件头信息、段信息、文件内容、符号表信息等，可根据实际需要选择。`objdump`更多可用参数及含义可通过命令`objdump --help`查看。

这里使用参数`-d`反汇编目标文件`hello.o`的所有代码段指令，并重定向到文件`a.txt`。具体命令如下：
``` shell
$objdump -d hello.o > a.txt
```
文件`a.txt`中包含所有相关函数的反汇编信息。这里仅列举函数`main`对应的反汇编内容：
``` shell
0000000000000000 <main>:
0:		02ffc063		addi.d       $r3,$r3,-16(0xff0)
4:		1c000005		pcaddu12i   $r5,0
8:		02c000a5		addi.d      $r5,$r5,0
c:		1c000004		pcaddu12i   $r4,0
10:		02c00084		addi.d      $r4,$r4,0
14:		54000000		bl          0 # 18 <main+0x18>
18:		00150004		or          $r4,$r0,$r0
24:		02c04063		addi.d      $r3,$r3,16(0x10)
28:		4c000020		jirl        $r0,$r1,0
```
为了便于阅读和理解，`objdump`将机器指令按三列显示。第一列是当前机器指令所在的内存地址，以十六进制表示。不过在此阶段，每个函数的起始地址都为0，最终在内存中的位置需要到链接阶段才能确定。龙芯指令是定长指令，长度固定为4字节，因此后续每条指令地址依次增加4，即4、8、c等。第二列是机器指令，同样用十六进制表示。第三列是对`hello.o`中每条机器指令的等价翻译，即将不易阅读的机器指令翻译成相对易读的汇编指令。

可以看出，`hello.o`和`hello.s`中的指令大部分相似，例如指令`addi.d $r3,$r3,-16(0xff0)`和`or $r4,$r0,$r0`等。区别在于，`.s`文件中除了汇编指令外，还有仅供汇编器使用的汇编器指令（如`.LC0`）和汇编宏指令（如`la.local`）。汇编器指令用于指导汇编器工作，例如`.LC0`用于告诉汇编器这里是本文件中第一个变量的内存位置。汇编宏指令是对架构真实汇编指令的封装，例如宏指令`la.local $r5,.LC0`会被翻译成LoongArch的`pcaddu12i $r5,0`和`addi.d $r5,$r5,0`。

还需要注意的是，指令`bl 0`表示要跳转的地址为0，因此此时还无法实现对函数`printf`的正确调用。这说明该阶段的目标文件还不能被计算机正确执行。只有在链接阶段将这个跳转地址修改为有效内存地址后，这段程序才可以有效执行。

机器指令生成阶段可以直接使用工具`as`完成，也可以使用带参数`-c`的`gcc`命令完成，具体示例如下：
``` shell
$ as hello.s -o hello.o
$ gcc -c hello.c -o hello.o
```

##	链接阶段

链接阶段使用的工具是`collect2`（`collect2`是链接器`ld`的封装）。该阶段的主要工作是将机器指令生成阶段得到的多个`.o`文件正确链接为一个文件。例如，本节开头显示的编译过程中的命令`collect2 -o hello crt1.o crti.o crtbegin.o hello.o crtend.o crtn.o`，就是将`crt1.o`到`crtn.o`等文件链接起来，并将结果写入目标文件`hello`。对于不能直接链接进来的动态库（如`libc.so`），也要在引用位置计算好地址，以便程序运行时能够正确找到并动态加载。

链接阶段有两个核心工作：符号解析和重定位。符号包括函数名和变量名。每个待链接的目标文件（如`hello.o`）都有一个符号表，表内包含当前文件中定义和使用到的所有符号，可使用命令`objdump -t hello.o`查看。符号解析会为各符号表中的符号定义和符号引用建立关联，并形成全局符号表。重定位则负责重新排列所有输入文件中的信息，并根据全局符号表重新计算各符号的最终位置。

使用`objdump`反汇编链接后生成的`hello`文件，显示结果如下：
``` shell
0000000000000570 <printf@plt>:
000000570:		1c00010f		pcaddu12i       $r15,8(0x8)
000000574:		28ea81ef		ld.d            $r15,$r15,-1376(0xaa0)
000000578:		1c00000d		pcaddu12i       $r13,0
00000057c:		4c0001e0		jirl            $r0,$r15,0
0000000000000580 <main>:
000000580:		02ffc063		addi.d    $r3,$r3,-16(0xff0)
000000584:		1c000005		pcaddu12i     $r5,0
000000588:		02c000a5		addi.d  $r5,  $r5,0
00000058c:		1c000004		pcaddu12i     $r4,0
000000590:		02c00084		addi.d        $r4,$r4,0
000000594:		54000000		bl     -40(0xfffffd8) # 000000570 <printf@plt>
00000059c:		00150004		or            $r4,$r0,$r0
0000005a0:		02c04063		addi.d        $r3,$r3,16(0x10)
0000005ac:		4c000020		jirl          $r0,$r1,0
```
与前文机器指令生成阶段产生的`hello.o`文件内容对比后不难发现，链接后的指令几乎没有变化，但指令存放地址发生了改变（见第一列）。`main`函数的起始地址（函数第一条指令所在地址）由之前的0变为0x000000580，后续指令地址依次增加4字节。该地址是`hello`程序运行时的有效虚拟地址。经过重定位过程，指令`bl 0`变为`bl -40(0xfffffd8)`，指令本身没有变化，但跳转地址被修正，即从当前地址0x000000594减去40字节即可得到`printf`函数地址。后面的备注信息`# 000000570 <printf@plt>`已经给出计算结果，`printf`的地址为0x000000570。
