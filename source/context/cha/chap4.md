#	指令调度

##	指令流水线和流水线冲突

指令流水线是指将每条指令的执行过程划分为若干阶段，使多条指令的不同阶段可以在同一个周期内同时进行，从而充分利用 CPU 核中的功能部件，提高指令吞吐量。

以经典5级流水线为例，一条指令的执行过程被分为取指、读寄存器、执行、访问内存和写回这5个阶段，如图10-1所示。


指令的每个阶段都占用固定时间（通常为一个处理器时钟周期）。取指阶段根据程序计数器（PC）访问指令缓存和指令 TLB，取一条或多条指令到指令存储器。读寄存器阶段用于读取该指令源寄存器中的内容。执行阶段用于完成算术或逻辑运算。访问内存阶段用于读写数据缓存中的内存变量。写回阶段将操作结果写回寄存器堆。

当第一条指令执行到读寄存器阶段时，第二条指令可以在同一时间段进入取指阶段；当第二条指令执行到读寄存器阶段时，第三条指令又可以开始取指，依此类推。指令流水线意味着在同一个时钟周期内，可以有多条指令分别处于不同流水级。由此可见，流水线技术可以提高处理器的指令吞吐量，明显缩短程序执行时间。龙芯3号处理器的基本流水线包括 PC、取指、预译码、译码1、译码2、寄存器重命名、调度、发射、读寄存器、执行、写回和提交，共12级流水。

大部分指令之间存在相关性，具体可分为3种情况：数据相关、控制相关和结构相关。如果当前指令需要使用上一条指令的结果，当前指令必须等待上一条指令执行完成，则这两条指令存在数据相关。如果当前指令为条件转移指令，下一条指令的执行取决于当前条件转移指令的执行结果，则这两条指令存在控制相关。如果两条指令使用同一功能部件，例如都使用 ALU 部件执行整数运算，或都使用 FPU 部件执行浮点运算，则这两条指令存在结构相关。

指令间的相关性会导致流水线阻塞。以数据相关为例，假设第 N 条指令将结果写回 r1 寄存器，第 N+1 条指令需要使用 r1 的值进行计算。在上述5级流水线中，第 N 条指令到第五阶段才能把结果写回寄存器 r1，而第 N+1 条指令在第二阶段就需要读取 r1 的值。这会导致第 N 条指令尚未将结果写回 r1 时，第 N+1 条指令就读取并使用旧值；如果不加控制，就会造成运算结果错误。简单等待可以解决这类数据相关问题，即让第 N+1 条指令在第二阶段等待3拍后再读取寄存器值，但这会引起指令流水线阻塞并导致性能下降。

流水线前递技术可以缓解指令间的数据相关问题，即后续指令不必等到前序指令将执行结果写回寄存器后才获得该结果。例如下面的指令：

``` asm
add.d r5, r4, r3
sub.d r6, r5, r3
```
这里第二条减法指令 sub.d 的计算用到了第一条加法指令 add.d 的结果，因此两条指令存在数据相关。使用流水线前递技术后，sub.d 指令计算时不必等待 add.d 指令完成写回阶段，而是在 r4 与 r3 的加法运算执行完成后即可获得结果，并继续执行 sub.d 指令的执行阶段。

但在多拍操作的情况下，前递技术的作用仍然有限。因为前递技术通常只能减少1～2拍等待，而对于下面这样的指令序列：

``` asm
load r1, addr
addi r1,r1,#2
```
由于 load 指令需要执行多拍且具体拍数不确定，流水线前递技术对此作用有限。因此，后文将介绍如何通过静态指令调度隔开相关指令，以避免流水线冲突。

再来看控制相关和结构相关造成的流水线阻塞。对于控制相关，由于在条件转移指令执行完成之前，处理器无法确定下一条要执行的指令地址，因此不能把下一条指令放入流水线中，只能等待该条件转移指令执行完毕后再开始下一条待执行指令的取指，这也会导致流水线阻塞。目前大多数处理器都针对这种情况采用分支预测技术，以尽量减少控制相关带来的流水线阻塞次数。结构相关引起流水线阻塞的原因是资源有限。例如，如果处理器只有一个乘法功能部件，那么一条乘法指令正在运算时，后续乘法指令只能等待，也会导致流水线阻塞。

##	指令调度

指令调度是指在不影响程序执行结果正确性的前提下，通过改变指令执行顺序来避免由指令相关引起的流水线阻塞，从而提升程序执行性能。指令调度分为静态调度和动态调度。动态调度由硬件自动完成，静态调度则由汇编语言编写人员或编译器在程序执行前对指令进行重新排序来实现。

在进行指令静态调度优化之前，需要了解现代处理器内部通常包含多个功能部件。不同类型的指令由不同功能部件执行，并且可能需要不同的执行拍数。例如，算术运算、逻辑运算和转移指令在定点 ALU 中执行，通常1拍即可完成；浮点运算在浮点 ALU 中执行，通常需要2～3拍，浮点乘/除法运算至少需要5～6拍；访存指令在访存部件中执行，其执行拍数不确定（与 Cache 命中情况密切相关），通常也需要多拍。

假设存在数据相关的浮点加载指令和浮点运算指令之间需要空1拍（记为指令延迟为1），两条存在数据相关的浮点运算指令之间需要空2拍（记为指令延迟为2），而其他存在数据相关的整型运算指令之间没有延迟。例如，要实现数组内每个元素与一个定值相加，其指令序列和指令延迟信息如下：
``` text
i1  Loop:      fld.f     fa0,   0(r1)
| 1
i2             fadd.f  fa2,   fa0,   fa1
| 2
i3             fsd.f     fa2,   0(r1)
i4             addi.w    r1,     r1,     -4
i5             bnez      r1,    Loop          
```

这是指令调度之前的指令序列，共5条指令（分别为 i1～i5）。i1 和 i2 之间的1表示 i1 和 i2 存在数据依赖（数据相关），且 i1 的指令延迟为1。i2 和 i3 也存在数据依赖，且指令延迟为2。i4 和 i5 虽存在数据依赖，但没有延迟。可以计算出，处理器执行完这5条指令需要8拍。对于这样的指令序列，可以通过调整指令间的执行顺序来减少指令延迟，具体可优化为如下形式：
``` text
i1  Loop:      fld.f     fa0,   0(r1)
| 1
i2             fadd.f  fa2,   fa0,   fa1
i4             addi.w  r1,     r1,     -4
i3             fsd.f   fa2,   4(r1)
i5             bnez    r1,    Loop          
```
在优化后的指令序列中，将 i3 和 i4 指令位置互换，同时将 i3 指令的存储位置从 0(r1) 调整为 4(r1)，以确保程序正确性。处理器执行完这5条指令仅需要6拍，比优化前减少了2拍。

一般而言，对于控制相关，软件层面可做的优化有限。但对于数据相关和结构相关，可以进行更细致的分析，充分利用指令间的延迟来提高程序执行效率。
