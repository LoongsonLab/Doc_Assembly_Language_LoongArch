#	指令融合和地址对齐

指令融合是指用执行效率更高的一条或几条指令替换多条指令，从而提高性能。例如：
``` text
shl   r3, 3
add.d r2, r2, r3
=>
alsl_d r2, r3, r2, 2
```
因为龙芯指令集提供了移位加指令 alsl，所以存在数据相关的 shl 和 add 两条指令可用一条 alsl 指令完成。

如果多线程程序对共享数据有保序要求，可能需要在写指令 st 前后添加屏障指令 dbar。此时，使用具有屏障功能的原子指令通常更高效，示例如下：
``` text
dbar 0
st.w r4, r12, 0
dbar 0
=>
amswap_db.w r0, r4, r12
```

访存应尽可能满足地址自然对齐。对非对齐内存地址进行访问（load 或 store）可能导致处理器花费额外内存周期，并执行更多指令。即使龙芯处理器已经支持硬件自动处理非对齐访存，使非对齐数据访存的开销低于软件处理方式，也仍会带来一定程度的性能下降。因此，有必要了解一些常用的数据对齐方式，例如：

-	将多字节整数和浮点数对齐到自然边界；

-	尽量使用存储对齐，而非加载对齐；

-	必要时填充数据结构，以保证正确对齐。

在龙芯指令集中，边界检查访存指令、原子访存指令，以及普通访存指令中的 LDX、STX 指令，强制要求访存地址自然对齐，否则将触发非对齐例外。对于其他常用普通访存指令，例如 LD.{B/H/W/D}、ST.{B/H/W/D}、LDX.{B/H/W/D}、STX.{B/H/W/D} 等，如果硬件实现了非对齐访存，且当前环境配置为允许非对齐访存，则这些指令支持非对齐访存。也就是说，当访存地址不是自然对齐时，硬件会处理非对齐访问并返回正确结果。LoongArch 支持硬件处理非对齐内存数据访存。要判断当前环境是否允许非对齐访存，可以编写一个简单的非对齐访存程序进行验证，也可以通过读取控制状态寄存器 MISC 来判断。
