#	循环展开

循环展开是一种针对循环体程序的优化技术。它通过多次复制循环体内部指令，减少或消除循环次数，从而降低循环索引递增和条件检查指令多次执行带来的性能开销。

例如，在10.4.2小节的循环指令中，指令 fld.f、fadd.f、fsd.f 与运算直接相关，而指令 addi、bnez 属于循环开销，可以通过循环展开减少或消除其执行次数。当循环次数较小时（例如循环次数为3），可以将循环全部展开，从而消除 addi、bnez 指令的使用，即写为：
``` asm
i1             fld.f    fa0,   0(r1)
i2             fadd.f  fa2,   fa0,   fa1
i3             fsd.f   fa2,   0(r1)
i4             fld.f    fa0,   4(r1)
i5             fadd.f  fa2,   fa0,   fa1
i6             fsd.f   fa2,   4(r1)
i7             fld.f    fa0,   8(r1)
i8             fadd.f  fa2,   fa0,   fa1
i9             fsd.f   fa2,   8(r1)
```

循环展开之前的循环体为5条指令，循环执行3次，共需执行15条指令。循环展开后，仅需执行9条指令即可完成同样功能。

对循环展开后的指令，还可以进一步进行指令调度优化。具体来说，可以通过使用不同寄存器和重排指令，减少指令相关带来的延迟，充分利用指令流水线。优化后的指令序列如下：
``` asm
i1             fld.f      fa0,   0(r1)
i4             fld.f      fa3,   4(r1)
i7             fld.f      fa4,   8(r1)
i2             fadd.f    fa2,   fa0,   fa1
i5             fadd.f    fa5,   fa3,   fa1
i8             fadd.f    fa6,   fa4,   fa1
i3             fsd.f     fa2,   0(r1)
i6             fsd.f     fa5,   4(r1)
i9             fsd.f     fa6,   8(r1)
```

通常在编译器领域，对于迭代次数较大的循环体会设置最大展开次数，常见取值为4次、8次或16次。仍以10.4.2小节的指令为例，如果迭代次数为1000，并按4次展开，展开后的指令序列如下：

``` asm
Loop:      fld.f      fa0,   0(r1)
           fld.f      fa3,   4(r1)
           fld.f      fa4,   8(r1)
           fld.f      fa5,   12(r1)
           fadd.f     fa2,   fa0,   fa1
           fadd.f     fa6,   fa3,   fa1
           fadd.f     fa7,   fa4,   fa1
           fadd.f     fa8,   fa5,   fa1
           fsd.f      fa2,   0(r1)
           fsd.f      fa6,   4(r1)
           fsd.f      fa7,   8(r1)
           fsd.f      fa8,   12(r1)
           addi.w     r1,    r1,    -16
           bnez       r1,    Loop          
```

因为循环展开了4次，指令 addi.w 中 r1 的累加值由原来的 -4 变为 -16。虽然 addi、bnez 指令没有被完全消除，但由于循环次数减少，循环体执行的总指令数也显著减少。

循环展开可以降低循环执行开销，但会增加代码空间，可能影响指令 Cache 的命中率。CPU 在指令 Cache 中找到所需指令称为命中，否则称为不命中；命中率是命中指令数占全部执行指令数的比例。因此，展开次数通常不宜过大，一般16次基本可视为展开次数上限。展开次数不宜过大的另一个原因是寄存器数量有限。循环展开后，如果存在空闲寄存器，就可以利用这些寄存器减少指令间的数据依赖，从而对展开后的指令做二次优化。但如果展开次数过大，缺少足够的空闲寄存器，此时要么选择将部分寄存器数据入栈保存，并在循环结束后再从栈上恢复；要么只能接受循环展开后数据依赖带来的部分性能损耗。
