#	访存指令

访存指令用于对内存中的数据进行读操作（访问）或写操作（存储）。LoongArch中的访存指令可分为普通访存指令、边界检查访存指令（访存前对地址合法性进行检查）、原子访存指令（能够原子性地完成对某个内存地址的读-修改-写操作序列）。在龙芯架构参考手册中，栅障指令不属于访存指令范畴，但由于栅障指令与数据访存具有一定关联性，因此本节也将其一并介绍。

##	普通访存指令

普通访存指令实现对指定内存地址的数据读写功能。读数据也称为加载，即从指定内存地址加载数据到指定寄存器；写数据也称为存储，即把指定寄存器中的数据存储到指定内存地址。读写数据的类型可以是字节、半字、字、双字。LoongArch支持的普通访存指令如表3-5所示。

表3-5中，对于加载指令中小于64位的数据（以后缀`.b`、`.h`、`.w`标识），通常需要进行符号扩展后再加载到指定寄存器。无论是从内存加载数据到寄存器，还是把寄存器数据写入内存，内存地址的计算方式都有两种：一种是基址加立即数偏移（常称为base+offset），此类访存指令的指令名前缀不带`x`，例如`ld.b`、`st.b`；另一种是基址加寄存器偏移（常称为base+index），此类访存指令的指令名前缀带`x`标识，例如`ldx.b`、`stx.b`。使用基址加立即数偏移的访存指令时，偏移值为有符号12位值（si12），可表示的偏移范围为[-2048, 2047]。

对于满足自然对齐的访存地址，可以使用表3-5中的`ldptr.w`、`ldptr.d`、`stptr.w`和`stptr.d`访存指令。由于其地址偏移量为16位值（si14<<2），因此相较于`ld.w`、`ld.d`、`st.w`、`st.d`指令，可支持更大地址偏移范围的数据访存。

表3-5中的指令`preld hint, rj, si12`用于从指定内存地址提前加载一个Cache行的数据到Cache中。指定内存地址的计算方式为寄存器rj的值与立即数si12相加。指令中的hint有0~31共32个可选值，用于表示预取类型。目前，hint=0定义为load预取至一级数据Cache，hint=8定义为store预取至一级数据Cache，其他hint值暂未定义，处理器执行时将其视同`nop`指令处理。

##	边界检查访存指令

边界检查访存指令与普通访存指令的基本功能相同，都用于从指定内存地址读取数据到寄存器，或将数据写入指定内存地址，读写数据类型可以是字节、半字、字、双字。二者区别在于，对指定内存地址执行读写操作前，边界检查访存指令会进行条件检查，确认该地址是否位于给定地址范围内；如果条件不满足，则终止读写操作并触发边界检查例外。LoongArch支持的边界检查访存指令如表3-6所示。

```{image} ../../img/ch3/t2p_3_6.png

:class: bg-primary
:scale: 80 %
```

表3-6中，所有指令的访存地址都来自寄存器rj，rk代表访存边界，且所有指令的访存地址均要求自然对齐，否则将触发非对齐例外。

什么情况下会用到带边界检查的访存指令？最常见的情况是数组下标越界。假设数组定义为`int array[100]`，则数组下标范围为0~99，访问`array[-1]`或`array[101]`都属于越界访问。C语言并不具备类似Java语言那样对程序员友好的动态防御功能，无法自动对程序中的数组下标取值范围进行严格检查（Java一旦发现数组越界访问就会抛出异常并终止程序）。例如，C语言中对数组`int array[100]`的越界下标赋值语句如下：
``` c
array[101] = 1;
```
此语句可以使用如下汇编指令实现：
``` asm
addi.w 	$r13, $r0, 1(0x1) 	#	加载立即数1到寄存器r13
st.w 	$r13, $r12, 0 		#	实现array[101] = 1。这里假设&array[101]为r12
```
指令`st.w r13, r12, 0`执行后可能带来两类安全隐患：程序立即异常，或程序运行一段时间后异常。编译器可以保证`array[0]~array[99]`所在内存区域可写，但`array[101]`所在内存区域的权限是不确定的。如果`array[101]`所在内存区域不可写（例如恰好进入只读代码区），那么`st.w`执行时会立即触发异常（通常异常信号为SIGBUS）。如果`array[101]`所在内存区域恰好可写，那么这条写指令`st.w`仍会正常执行，但数值会写入数组范围外的地址空间，可能破坏另一个合法占有该地址空间的变量或指针值。程序继续运行一段时间后就可能发生错误或崩溃，此时问题定位会变得非常困难，因为已经远离错误现场。

为了让问题在第一时间暴露出来并降低调试难度，可以使用带边界检查的访存指令实现数组的安全访问。

:::{tip}
边界检查访存指令仅在LA64架构上支持，在LA32架构上没有相关指令。如果要在LA32架构实现类似功能，可以使用其他基础逻辑运算指令完成。
:::

##	栅障指令
栅障类型分为数据栅障和指令栅障。数据栅障用于防止处理器核对某些访存指令进行乱序执行，指令栅障用于保证被修改后的指令能够被正确执行。
:::{note}
乱序执行：当CPU准备执行某条需要等待的指令（例如访存指令的读操作数因Cache Miss尚未准备好，或遇到比较耗时的乘法指令）时，可以先让排在后面且没有数据相关的指令执行，从而避免流水线阻塞带来的性能下降。
:::

通常，数据栅障有多种类型。常见的读栅障（常被描述为LoadLoad）用于确保数据栅障指令前后读内存指令的有序性，即只有数据栅障指令前面的读内存指令执行完成后，数据栅障指令后面的读内存指令才可以执行；写栅障（常被描述为StoreStore）用于确保数据栅障指令前后写内存指令的有序性；完全栅障（常被描述为AnyAny）用于确保数据栅障指令前后所有访存指令的有序性，即只有数据栅障指令前面的所有访存指令执行完成后，数据栅障指令后面的访存指令才可以执行。

在表3-7的`dbar hint`指令中，操作数hint用于指示栅障的同步对象和同步程度。hint默认值为0，代表完全栅障。目前，龙芯基础指令集中仅实现了完全栅障，其他类型栅障后续会陆续支持。

表3-7中的`ibar hint`指令用于完成处理器核内部store操作和取指之间的同步，操作数hint为0。

:::{note}
现代处理器通常采用多级缓存（Cache）结构。其中，处理器内私有的一级Cache又分为数据缓存（DCache）和指令缓存（ICache），分别用于存放程序数据和指令。由于数据缓存和指令缓存没有直接联系，当指令被动态修改（程序已经执行）时，需要软件保证修改后的指令被写回内存，并使对应ICache位置上的旧指令失效。
:::

:::{note}
弱一致性模型是存储一致性模型的一种。

在弱一致性模型中，同步操作和普通访存需要区分开来。当程序中存在写共享单元（或变量）时，程序员必须使用架构所定义的同步操作保护对写共享单元的访问，以保证多个处理器核对写共享单元的访问互斥，从而保证程序正确性。

这里所提的“架构所定义的同步操作”即栅障指令。
:::
:::{note}
数据相关：在程序中，如果两条指令访问同一个寄存器或内存单元，且这两条指令中至少有一条会写该寄存器或内存单元，则认为这两条指令存在数据相关。

例如，指令`add.w r5,r4,r3`和指令`sub.w r7,r5,r6`存在数据相关，因为二者都使用了r5，且`sub.w`的执行依赖`add.w`对r5的写入结果。
:::

解决此问题的做法是在写进程中使用数据栅障指令`dbar`，从而保证写数据和写标识的有序性。具体如下：
``` asm
st.d 	val,data
dbar 	0 		#	确保其前后两条访存指令的顺序执行
st.d 	1,tag
```
同理，读进程中两条没有数据相关的读访存指令也可能发生乱序执行，即可能在尚未判断标识区tag的情况下提前读取数据区data。因此，也需要加入数据栅障指令来保证顺序，具体如下：
``` asm
# 	读进程
ld.d 	reg, tag 	# 	读标识区tag
dbar 	0
beqz 	reg, L 		# 	标识如果为0，则跳转到L执行nop
ld.d 	val, data 	#  	否则证明标识区为1，执行读数据区data
L:	nop
```
对于多进程共享区域数据的读写，加入指令`dbar 0`可以避免处理器乱序执行可能导致的共享区域数据不一致问题。

##	原子访存指令

原子访存指令用于确保对指定内存的“读-修改-写”操作序列具有原子性，即从执行效果看，读-修改-写整个过程不可分割且不会被中断。其中，修改动作可以包括两个源操作数的交换、加法运算、与、或、异或、取最大值、取最小值，甚至自定义动作等。LoongArch支持的原子访存指令有两类：内存原子操作（Atomic Memory Operation，AMO）和连锁加载/条件存储（Load-Linked/Store-Conditional，LL-SC），具体指令如表3-8所示。

在表3-8中，AMO指令中的寄存器rj存放待操作的内存地址，内存旧值保存到rd，内存新值来自内存旧值和rk的某种运算。具体运算包括数据交换（amswap）、加法运算（amadd）、与（amand）、或（amor）、异或（amxor）、取最大值（ammax）、取最小值（ammin）。

AMO中带`_db`标识的指令，例如`amswap_db.w`、`amor_db.d`等，除可以完成原子内存操作外，还能实现数据栅障功能。也就是说，当此AMO指令被允许执行前，同一处理器核中先于该指令的所有访存操作都已经完成；只有等此AMO指令完成后，同一处理器核中后于该指令的访存操作才被允许执行。此类栅障效果也称为完全栅障，即前文提到的AnyAny类型。

LL-SC中的`ll.w`、`ll.d`用于从指定内存（地址为rj+si14）加载一个字或双字的数据到寄存器rd，同时记录该内存地址并设置标记（LLbit置为1）；`sc.w`、`sc.d`用于将寄存器rd的值写回指定内存（地址为rj+si14）。执行`sc`指令时会检查标记LLbit，只有当LLbit为1时才真正产生写动作并将寄存器rd置1；否则不写入内存，并将寄存器rd置0以表明写失败。在配对的LL-SC执行期间，如果其他处理器核对该地址执行写操作，则会导致LLbit置0。

下面分别说明两类原子访存指令的使用方法和注意事项。

1. 连锁加载/条件存储(LL-SC)

LL-SC对一个内存单元的原子操作维护需要由软件完成。当软件必须成功完成一个原子的“读-修改-写”访存操作序列时，需要构建一个循环来反复执行LL-SC原子指令对，直到`sc`指令成功完成。为了构建这个循环，`sc`指令会将其执行成功与否的标志写入寄存器rd。

2. 内存原子操作(AMO)

AMO指令涵盖了大部分简短且常用的运算。对于前文使用LL-SC原子访存指令对实现`a=a+1`的原子操作，使用AMO指令更简单方便。
:::{tip}
AMO指令仅在LA64架构下支持。
:::

:::{tip}
使用原子访存指令时需要注意，rd和rj的寄存器号不能相同，rd和rk的寄存器号也不能相同，否则可能触发例外或导致执行结果不确定。
:::
