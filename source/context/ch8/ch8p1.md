#	内嵌汇编基本格式

内嵌汇编的基本格式如下：
``` c
asm asm-qualifiers (
"Assembler Template"  //汇编模板
: OutputOperands //输出操作数
: InputOperands //输入操作数
: Clobbers //破坏描述
);
```
内嵌汇编以 asm() 格式表示，括号内分为4个部分：Assembler Template，即汇编模板，其中包含0条或多条内嵌汇编指令；OutputOperands，即输出操作数，可以有0个或多个；InputOperands，即输入操作数，可以有0个或多个；Clobbers，即破坏描述，可以没有，也可以有多个。各部分之间使用“:”分隔。asm-qualifiers 为 asm() 的限定符，可以为空，也可以是 volatile、inline、goto 中的任意一个。

其中，汇编模板部分必不可少，但可以为空，即 `""`。汇编模板也可以包含一条或多条内嵌汇编指令，每条指令都以双引号 `""` 为单位，并以 `\n\t` 结尾或通过换行分隔。例如，下面两段内嵌汇编写法都是合法的：

``` c
  asm("");
```
``` c
asm("add.d %0,%1\n\t"
	"add.d %0,%2\n\t"
	:"=r"(ret)
	:"r"(a),"r"(b)
);
```
这里的内嵌汇编 `asm("")` 中没有内嵌汇编指令，编译器不会为其生成任何汇编指令。第二段内嵌汇编包含两条汇编指令，但没有显式使用固定寄存器，因此破坏描述部分可以省略。

如果内嵌汇编中只有汇编指令，不需要输出操作数、输入操作数和破坏描述，则后面的“:”都可以省略。例如：
``` c
asm("break 0");
```
这里仅在程序中插入一条中断指令，不需要其他变量参与，因此内嵌汇编中执行LoongArch中断指令 `break 0` 即可。

还需要说明的是，asm 是 __asm__ 的别名，所以上述语句也可以写成：
``` c
__asm__("break 0");
```
注意：如果内嵌汇编只使用了后面的部分，而前面的部分为空，那么前面的部分也需要使用“:”分隔。例如，下面的示例中有输入操作数，但没有输出操作数和破坏描述，因此输出操作数前的“:”不能省略，而后面的破坏描述可以省略。这样规定是为了让编译器能够正确识别各个部分。

``` c
 asm("move $4,%0\n\t"
	:                         //输出操作数
	:"r"(a)                   //输入操作数
);
```

在 asm 模板中可以使用符号 `/*...*/` 或 `//` 添加注释。通常，`/*...*/` 用于块注释，`//` 用于行注释。

从上面这段内嵌汇编还能看出，指令中的操作数不仅可以是占位符，也可以是通用寄存器或浮点寄存器中的任意寄存器。使用寄存器作为操作数时，其写法与汇编源程序相同，即寄存器名前需要添加符号 `$`，`$` 后可以跟寄存器编号（如 `$4`），也可以跟寄存器别名（如 `$a0`）。上面这条指令实现了将C语言变量 a 的值存入通用寄存器 r4。

##	输入操作数和输出操作数

在内嵌汇编格式中，输入操作数和输出操作数里的每个操作数，都由一个带双引号 `""` 的约束字符串和一个带括号的C语言表达式或变量组成。例如，本章开头内嵌汇编中的 `"r"(src)`，r 为约束符，src 为C语言变量。当存在多个输入操作数或多个输出操作数时，多个操作数之间使用“,”分隔。内嵌汇编指令会对输入操作数和输出操作数统一编号，使用 `%num` 的形式依次表示每个操作数，num 为从0开始的非负整数。例如，一个输出操作数和两个输入操作数的内嵌汇编示例如下：
``` c
  asm("add.d %0,%1,%2\n\t"
	:"=r"(ret)         //输出操作数，也是第0个操作数
	:"r"(a),"r"(b)     /*输入操作数，也是第1个操作数和第2个操作数*/
);
```
这里使用LoongArch指令 add.d 实现了C语言中 `ret = a + b` 的操作。两个输入操作数 `"r"(a)` 和 `"r"(b)` 之间使用“,”分隔。%0 代表操作数 `"=r"(ret)`，%1 代表操作数 `"r"(a)`，%2 代表操作数 `"r"(b)`。

每个操作数前面的约束字符或字符串表示对后面C语言表达式或变量的限制条件。编译器会根据该约束条件决定相应的处理方式。例如，`"=r"(ret)` 中的“=r”包含两个约束条件：“=”表明此操作数是输出操作数，因此不会出现在输入操作数列表中；“r”表明需要为此操作数分配一个寄存器，即将其与某个寄存器关联。约束字符还有很多，有些还与特定体系架构相关，8.2节会详细列举。

输入操作数通常是C语言变量，也可以是C语言表达式。例如：
``` c
asm("move %0,%1\n\t"
	:"=r"(ret)
	:"r"(&src+4)
);
```
这里输入操作数 `&src + 4` 就是C语言表达式。编译器会先将地址 `&src + 4` 分配给一个通用寄存器，再参与指令 move 的操作，即赋值给变量 ret。

输出操作数必须是左值，编译器会对此进行检查。简单地说，以赋值符号“=”为界，“=”左边的是左值，右边的是右值。因此，输出操作数必须使用“=r”标识自己。输入操作数既可以是左值，也可以是右值。输出操作数也可以有多个；当有多个输出操作数时，每个输出操作数都需要使用“=”标识。例如，LoongArch中用于读取当前处理器核计时器的指令 `rdtime.d rd, rj`，其操作数 rd 和 rj 都是输出，rd 用于读取 counter 值，rj 用于读取 counterid。那么，使用此指令的内嵌汇编写法可以为：
``` c
unsigned long count = 0;
int count_id = 0;
asm(  "rdtime.d %0,%1\n\t"
	:"=r"(count),"=r"(count_id)
); 
```
默认情况下，输出操作数权限是只写（Write-Only）的，但编译器不会对此做额外检查。这个特性有时会给编程带来问题。假设在内嵌汇编指令中误将输出操作数当作右值使用，编译器在编译时不会报错，但程序运行后可能无法得到预期结果。为此，可以使用限制符“+”将输出操作数的权限改为可读可写。例如：
``` c
asm("add.d %0,%0,%1\n\t"
	:"+r"(ret)
	:"r"(a)
);
```
这就实现了变量 ret 的累加功能，即 `ret = ret + a`。也可以使用数字限制符“0”达到类似目的。
``` c
asm("add.d %0,%1,%2\n\t"
	:"=r"(ret)
	:"0"(ret),"r"(a)
);
```
这里数字限制符“0”的含义是输入操作数 ret 和第0个输出操作数使用同一地址空间。数字限制符只能用于输入操作数部分，而且必须指向某个输出操作数。数字限制符在日常编程中并不常见，此处了解即可。

##	破坏描述

内嵌汇编中的破坏描述部分用于声明在汇编指令部分存在写操作的寄存器或内存，从而通知编译器这些寄存器或内存在此内嵌汇编中会被破坏（被写），需要提前保存，并在内嵌汇编指令完成后恢复旧值。破坏描述部分有两种声明方式：声明寄存器和声明 memory。下面分别介绍。

1. 	破坏描述寄存器

通常，内嵌汇编程序中更多使用C语言变量，而变量关联的寄存器由编译器根据整个函数的上下文分配。分配结果通常是未被使用的寄存器，或已经完成保存处理的寄存器。但是，汇编指令部分也可以直接使用LoongArch寄存器，并对其进行修改（写操作）。如果没有在破坏描述部分声明这些寄存器，编译器在编译内嵌汇编时就不会进行相应检查和保护，可能因为某个寄存器旧值未保存而被修改，导致程序出错甚至发生致命异常。例如，下面是在汇编指令中使用寄存器却没有做破坏描述的内嵌汇编：
``` c
    asm("li.w $ra, 0\n\t");
```
这段内嵌汇编将数值0写入通用寄存器 ra。在LoongArch ABI中，通用寄存器 ra 用于存放函数返回地址。这里寄存器 ra 被改写为0，却没有通知编译器，将导致此段内嵌汇编所在函数无法找到原返回地址而无法正常返回。正确做法是在破坏描述部分添加对寄存器 ra 的声明，告诉编译器此寄存器的值会被改变，声明如下：
``` c
    asm("li.w $ra, 0\n\t" :::"$ra");
```
如果内嵌汇编中有多个指定寄存器会被破坏，建议在破坏描述部分声明所有被修改的寄存器。声明多个寄存器时，寄存器之间使用“,”分隔，具体写法如下：
``` c
asm(
	"add.d $a3, $a1, $a2\n\t"
	"move  $v0,%0\n\t"
	:"=g"(ret)
	:"r"(a),"r"(b)
	:"$a3", "$v0"
);
```
此示例中，寄存器 a3 和寄存器 v0 都是目的寄存器，均存在写操作，因此需要通过破坏描述通知编译器保存和恢复这些寄存器的旧值。

2.	破坏描述memory

通常，GCC编译器会对程序的指令生成进行一些优化（如使用参数 -O2、-O3 时）。例如，在保证程序正确性的前提下，编译器会尽可能利用寄存器作为缓存，以减少访存指令的生成。先看下面这段C语言语句：

``` c
a += 1;
b += a;
```
实现语句 `a += 1` 需要3条汇编指令：从内存加载变量 a 的值到寄存器，与立即数1进行加法运算，再将运算结果写回内存。实现语句 `b += a` 需要4条汇编指令：从内存加载变量 b 的值到寄存器，从内存加载变量 a 的值到寄存器，进行加法运算，并将结果写回内存。在没有任何优化的情况下，这两条语句需要7条汇编指令完成。但是可以看出，执行语句 `b += a` 时，完全可以省略从内存加载变量 a 的值到寄存器的过程，直接使用执行 `a += 1` 时变量 a 所在的寄存器即可。最终编译结果仅需6条汇编指令。查看GCC编译器生成的结果，也确实如此。

``` asm
ldptr.w   $r12,$r4,0                 #从内存加载变量a的值
addi.w    $r12,$r12,1(0x1)           #加法运算
stptr.w   $r12,$r4,0                 #将结果写回变量a所在内存
ldptr.w   $r13,$r5,0                 #从内存加载变量b的值
add.w     $r12,$r13,$r12             #加法运算（复用r12的结果）
stptr.w   $r12,$r5,0                 #将结果写回变量b所在内存
```
但是当我们在这段C语言语句中插入一段内嵌汇编，具体如下所示：
``` c
a += 1;
asm volatile("":::"memory");
b += a;
```
此时，编译器生成的对应汇编指令会发生变化，具体如下所示：
``` asm
ldptr.w   $r12,$r4,0              #从内存加载变量a的值
addi.w    $r12,$r12,1(0x1)
stptr.w   $r12,$r4,0
ldptr.w   $r12,$r5,0
ldptr.w   $r13,$r4,0              #再次从内存加载变量a的值
add.w     $r12,$r12,$r13
stptr.w   $r12,$r5,0
```
可以看出，在C语言语句中插入一段带 memory 破坏描述的内嵌汇编后，生成指令中的 `b += a` 并没有复用 `a += 1` 的结果，而是再次从内存加载变量 a 的值到新的寄存器 r13，然后再进行加法运算。这里的 memory 相当于告诉编译器不要继续依赖此前的寄存器缓存结果。

破坏描述 memory 的功能可描述为：通知编译器 asm 中可能对内存做了修改（写操作），因此在 asm 前后不要对访存相关语句做值假设（优化），而应及时刷新内存，即把寄存器数据写入内存，或从内存重新读取最新数据，以便获取内存中的最新值。下面再列举一个更实际的例子。考虑下面这段代码的输出结果：
``` c
int dest = 1;
int add_value = 2;
int old_value;
asm volatile ( "amadd.w %0, %1, %2 \n\t"
: "=&r" (old_value)
: "r" (add_value),  "r" (&dest)
:
);
printf("old_value=%d dest=%d\n", old_value, dest);
```

这段代码的功能是通过原子指令 amadd.w 实现一个加法操作，具体为对变量 dest 与变量 add_value 做加法运算，将结果写回 dest，同时将 dest 的旧值写到 old_value。期望结果是 `dest = 3`，`old_value = 1`。而实际结果却是 `dest = 1`，`old_value = 1`。问题出在哪里？先看这段代码对应生成的汇编指令：
``` asm
addi.w    $r12,$r0,2(0x2)    //add_value
addi.d    $r13,$r3,12(0xc)   //加载dest地址到r13
amadd.w   $r5,$r12,$r13      //取dest地址中的旧值加2后写回dest地址
addi.w    $r6,$r0,1(0x1)     // 加载dest数据1到r6
bl        -352(0xffffea0) # 1200005a0 <printf@plt> //输出数据
```
从指令 `addi.w $r6,$r0,1(0x1)` 可以看出，编译器并没有发现这段内嵌汇编对 dest 进行了写操作。因此，在调用 printf 函数之前，编译器没有重新读取 dest 所在内存的值，而是使用 addi.w 指令直接为参数寄存器 r6 赋值为1，导致 printf 输出的 dest 值仍为1。要让 `dest + 2` 的结果能够被观察到，就需要使用 memory 描述符。这段内嵌汇编的正确写法如下：
``` c
asm volatile ( "amadd.w %0, %1, %2 \n\t"
	: "=&r" (old_value)
	: "r" (add_value),  "r" (&dest)
	: "memory"
);
```
此时再查看其生成的汇编指令：
``` asm
addi.w   $r12,$r0,2(0x2)   //add_value
addi.d   $r13,$r3,12(0xc)  //加载dest地址到r13
amadd.w  $r5,$r12,$r13     //取dest地址中的旧值加2后写回dest地址
ldptr.w  $r6,$r3,12(0xc)   //加载dest地址中的数据到r6
bl        -352(0xffffea0) # 1200005a0 <printf@plt> //输出数据
```
可以发现，此时在调用 printf 函数之前，参数寄存器 r6 的值是通过读取 dest 所在内存地址获得的。amadd.w 指令已经将 `dest + 2` 的结果值3写回 dest 所在内存地址，因此 ldptr.w 指令中 r6 获取到的值为3。

##	有名操作数

从GCC 3.1版本开始，内嵌汇编支持有名操作数，即可以在内嵌汇编中为输入操作数、输出操作数命名。名字形式为 `[name]`，其中 name 可以由大小写字母、数字、下画线等组成，并放在每个操作数前面。在汇编指令中使用有名操作数的形式为 `%[name]`，区别于前文一直使用的操作数索引形式 `%num`。一段使用有名操作数的内嵌汇编如下：
``` c
asm("add.d %[out],%[in1],%[in2]\n\t"
	:[out]"=g"(ret)
	:[in1]"r"(a), [in2]"r"(b)
);
```
这段内嵌汇编为每个操作数都定义了名字，分别为 out、in1 和 in2，对应变量 ret、a 和 b。汇编指令中的操作数既可以使用前文介绍的 `add.d %0, %1, %2` 形式，也可以使用操作数名字，即 `add.d %[out], %[in1], %[in2]`。当然，也可以只为输出操作数或输入操作数中的一部分命名。例如：
``` c
asm("add.d %[out],%1,%2\n\t"
	:[out]"=g"(ret)
	:"r"(a),"r"(b)
);
```
这里只为第0个操作数 ret 取了名字。后面的第1个操作数和第2个操作数在使用时仍采用序号形式 %1、%2。
