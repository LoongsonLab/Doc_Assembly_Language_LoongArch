#	限制符volatile

使用 volatile 限制符的内嵌汇编通常不会被GCC编译器优化删除或重排。GCC编译器内置了许多优化功能（使用 -O 参数时生效），例如，当检测到 asm() 中的输出操作数没有被当前程序上下文使用时，编译器可能认为这段内嵌汇编是冗余的并删除它；当检测到循环体内部的内嵌汇编总是返回相同结果时，编译器也可能将这段内嵌汇编移动到循环体外部。如果这些优化并非预期行为，可以使用 volatile 限制符通知编译器保留该内嵌汇编。例如，在程序中添加一条断点指令进行代码调试时，通常写法如下：

``` c
asm volatile("break 0\n\t");
```

如果此内嵌汇编没有 volatile 修饰符，且内部仅有一条 `break 0` 指令，没有与当前函数中的任何有效变量关联（即可认为不存在数据依赖关系），那么GCC在编译过程中很可能会优化掉此内嵌汇编，导致生成的 .o 二进制文件中不存在 `break 0` 指令。
