#	没有函数栈的汇编源程序

第05章介绍LoongArch ABI时提到，函数通常以申请函数栈开始，用于保存返回地址、帧指针、局部变量等。GCC编译器生成函数入口代码时，通常也会分配函数栈，最小为16字节。例如，要实现一个简单的两个整数加法运算，C语言实现可以写为：
``` c
int myadd(int a,int b){
	return a+b;
}
```
使用GCC编译器将该C语言函数编译为汇编源文件后，其内容如下：
``` asm
myadd:
	addi.d 		$r3, $r3, -32 		#	申请栈空间
	st.d 		$r22, $r3, 24 		# 	将原fp值保存到栈上
	add.d 		$r22, $r3, 32 		#	将fp指向当前函数栈底
	or 			$r13, $r4, $r0 		#	保存a0和a1到栈
	or 			$r12, $r5, $r0 		#
	slli.w 		$r13, $r13, 0
	st.w 		$r13, $r22, -20
	slli.w 		$r12, $r12, 0
	st.w 		$r12, $r22, -24
	ld.w 		$r13, $r22, -20 	#	从栈上加载a0和a1
	ld.w 		$r12, $r22, -24
	add.w 		$r12, $r13, $r12 	#	加法运算
	or 			$r4, $r12, $r0 		#	设置返回值
	ld.d 		$r22, $r3, 24 
	addi.d 		$r3, $r3, 32
	jr 			$r1 				#	函数返回
```
按照LoongArch ABI约定，函数开始时通常会先申请栈空间，并将必要寄存器（如 fp、参数寄存器等）保存到栈上；函数退出前再恢复必要寄存器并释放栈空间。按此约定，一个简单的加法运算函数在没有强制内联等优化支持时，可能生成16条指令（如上所示）。如果直接编写汇编源文件 test.S 来实现同等功能，则可以用2条指令完成。
``` asm
myadd:
	add.d 	$v0, $a0, $a1
	jirl 	$zero, $ra, 0
```
编写汇编程序时，如果已经确认该函数不会破坏任何需要保存的寄存器，就可以省去函数栈的分配与释放，也无需保存和恢复相关寄存器。因此，上述功能最终仅用2条指令即可实现。由此可见，编写汇编程序可以为性能优化提供更大的空间。
