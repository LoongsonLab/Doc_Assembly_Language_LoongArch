#	基础指令类

【例1】 32位数的加法运算
``` asm
add.w 	$r5, $r2, $r1
```
这条指令将源寄存器 r2 与源寄存器 r1 相加，并将结果写入目的寄存器 r5。add.w 指令既可以用于 LA32 架构，也可以用于 LA64 架构。在 LA32 架构中，寄存器宽度（GLEN）和操作数类型相同，因此可以直接运算并赋值。在 LA64 架构中，add.w 的运算过程是仅取源操作数 r2、r1 的低32位参与加法运算，再将所得结果的低32位进行符号扩展后写入目的寄存器 r5。计算过程如下：
``` asm
add.w 	$r5, $r2, $r1 	# 	LA32: r5 = r2 + r1
add.w 	$r5, $r2, $r1 	#	LA64: r5[63:0] = SignExtend(r2[31:0] + r1[31:0])
```
LA64 指令集中其他32位数运算指令，例如 sub.w、addi.w、mul.w、div.w 等，其运算过程都与 add.w 类似，需要对运算结果进行符号扩展，并将扩展后的结果写入目的寄存器。

【例2】 64位数的加法运算
``` asm
add.d 	$r5, $r2, $r1 	# 	r5[63:0] = r2[63:0] + r1[63:0]
```
指令 add.d 仅用于 LA64 架构。进行加法运算时，源操作数 r2 和 r1 取全部64位，相加结果直接写入 r5。

【例3】 有进位的加法运算
``` asm
add.w 	$r5, $r1, $r1 	#	假设r1为2147483647
```
这条指令实现两个相同正整数 2147483647（0x7FFFFFFF）的加法运算，最终目的寄存器 r5 的值在 LA32 架构上为 0xFFFF FFFE，在 LA64 架构上为 0xFFFF FFFF FFFF FFFE。对应的十进制数是 -2，而不是期望的 4294967294。原因在于寄存器最高位（LA32 架构上为[31]，LA64 架构上为[63]）表示符号位，符号位为0表示正数，为1表示负数。剩余低31位或63位才是数值部分。对于两个32位正整数 2147483647 而言，加法结果为 4294967294，其最高位[31]的值为1，导致结果被解释为负数。当同符号数相加或异符号数相减时，进位可能导致结果高位符号改变，这种情况称为溢出。

判断溢出并不复杂。如果两个数的最高位相同，但相加后的结果最高位与这两个数不同，即可判断为溢出。例如，两个正整数相加后结果可能为负数，两个负整数相加后结果可能为正数；对于减法运算，正数减负数的结果可能变为负数，负数减正数的结果可能变为正数。因此，编写汇编指令时需要注意这一点。在 RISC 风格的 ARM 体系架构中，有专门的程序状态寄存器（Current Program Status Register，CPSR），用于保存进位、正负、溢出标志等运算结果状态信息。LoongArch 中没有设计类似 CPSR 功能的寄存器，但当程序需要处理运算结果进位或溢出时，可以通过目的寄存器和源寄存器的符号位是否一致来判断。

【例4】 带立即数的32位加法运算
``` asm
addi.w 	$r5, $r2, 100
```
这条指令实现32位源寄存器 r2 与十进制数100相加，并将结果写入目的寄存器 r5。表3-1中对 addi.w 指令使用的立即数规定为 si12，说明 addi.w 指令支持的立即数范围为 [-2048, 2047]。如果立即数超出这个范围，开发人员仍然使用此指令进行带立即数的加法操作，将会导致结果错误。当立即数超出规定范围时，需要先将立即数加载到寄存器，再使用不带立即数的 add.w 指令进行运算。

【例5】 实现与十进制数4098（十六进制表示为0x1002）的32位加法运算
``` asm
lu12i.w $r1, 0x1
ori 	$r1, $r1, 0x2
add.w 	$r5, $r2, $r1
```
立即数4098已经超出了 addi.w 指令支持的立即数范围，因此这里先通过 lu12i.w 和 ori 两条指令共同将4098加载到寄存器 r1 中，再通过 add.w 完成加法运算。其中，`lu12i.w r1, 0x1` 的功能是将4098中超过12位的部分（即0x1）加载到寄存器 r1，结果为0x1000；`ori r1, r1, 0x2` 的功能是将寄存器 r1 的值与4098的低12位（即0x002）进行逻辑或运算，并将结果4098（0x1002）写入寄存器 r1。这样，最终的4098就被加载到寄存器 r1 中。

LoongArch 中立即数加载的相关指令除 lu12i.w 外，还可以结合使用 lu32i.d、lu52i.d，分别实现52位、64位立即数的加载。具体可分为如下情况。

(1)小于12位的立即数加载：
``` asm
addi.d rd, r0, imm
```
当要加载的立即数小于12位时，可以通过与寄存器 r0（其值永远为0）的加法运算将其加载到寄存器。

(2)大于12位但小于32位的立即数加载：
``` asm
lu12i.w rd, imm[31:12]
ori 	rd, rd, imm[11:0]
```
对于大于12位但小于32位的立即数，需要使用上面两条指令实现加载。指令 lu12i.w 完成立即数 imm 高20位的加载，ori 完成 imm 低12位与已加载高20位的逻辑或运算，从而实现32位立即数加载。

(3)大于32位但小于52位的立即数加载：
``` asm
lu12i.w rd, imm[31:12]
ori 	rd, rd, imm[11:0]
lu32i.d rd, imm[51:32]
```
对于大于32位但小于52位的立即数，按52位立即数加载，需要3条指令完成。前两条指令完成立即数 imm 的低32位加载。指令 lu32i.d 实现 imm 高20位加载，并将其与低32位拼接，从而实现52位立即数加载。

(4)大于52位的立即数加载：
``` asm
lu12i.w rd, imm[31:12]
ori 	rd, rd, imm[11:0]
lu32i.d rd, imm[51:32]
lu52i.d rd, rd, imm[63:52]
```
对于大于52位的立即数，按64位立即数处理，需要4条指令完成加载。前3条指令完成立即数 imm 的低52位加载。指令 lu52i.d 实现 imm 高12位加载，并将其与低52位拼接，从而实现64位立即数加载。

可以看出，立即数加载较为烦琐。为了减少程序员编写代码的负担，汇编器支持立即数加载伪指令 `li.w rd, imm32` 和 `li.d rd, imm64`，分别用于32位以内和64位以内的立即数加载。这样，程序员编写汇编代码时不需要关注待加载立即数是小于12位、32位、52位还是64位，汇编器会根据立即数的实际长度，将 li.w 和 li.d 指令对应到上述几种情况。因此，当需要将立即数4098（十六进制为0x1002）加载到寄存器 r4 时，可以直接使用如下指令：
``` asm
li.w 	$r4, 0x1002
```
【例6】 带移位的64位数加法运算
``` asm
alsl.d 	$r5, $r4, 3 	# 	r5[63:0] = (r4[63:0] << (3+1)) + r5[63:0]
```
这条指令实现类似 C 语言中 `b = (a << 4) + b;` 语句的运算。其中，假设寄存器 r4 存放变量 a 的值，寄存器 r5 存放变量 b 的值，位移量为4（3+1），结果写入 r5。

表3-1中共有3条带移位的加法运算指令，分别是 alsl.w、alsl.d、alsl.wu，这也是龙芯基础指令集中为数不多的四操作数指令。这3条指令都用于实现带移位（左移）的加法操作，区别在于源操作数位宽不同。其中，alsl.w 与 alsl.wu 都用于32位操作数的移位加运算。对于 alsl.w，需要对运算结果进行符号扩展后写入目的寄存器；对于 alsl.wu，则需要对运算结果进行零扩展后写入目的寄存器。这两条指令的位移量都限制为 sa2，即位移量范围是 [1, 4]。当位移量超出此范围时，例如位移量为5，如果要实现同样功能，就需要额外使用一条移位指令和一条加法指令。

【例7】 乘法/除法运算
``` asm
mul.w 	$r5, $r2, $r1
div.w 	$r5, $r2, $r1
```
这两条指令分别实现源寄存器 r2 与源寄存器 r1 的乘法运算和除法运算，并将所得乘积和商写入目的寄存器 r5。与加法指令 add.w 类似，mul.w、div.w 既可以用于 LA32 架构，也可以用于 LA64 架构。在 LA32 架构中，由于寄存器宽度和操作数类型相同，因此直接赋值即可。在 LA64 架构中，mul.w、div.w 的运算过程是仅取源操作数低32位参与运算，再将所得结果的低32位符号扩展到64位后写入目的寄存器。

两个整数进行乘法运算时，需要考虑溢出问题；两个整数进行除法运算时，需要考虑余数问题。乘法指令溢出是指对于 mul.w 指令，乘积结果超过31位；对于 mul.d 指令，乘积结果超过63位。除法指令余数是指对于 div.w、div.d 指令，源操作数不能被整除而出现余数的情况。

假设示例中的寄存器 r1 的值为 0x7FFF FFFF，寄存器 r2 的值为 0x4，期望的数学乘积结果应为 8589934588（0x1FFFFFFFC）。但由于当前使用的是 mul.w 指令，实现的是寄存器 r1 和 r2 的低32位乘法运算，并将运算结果低32位进行有符号扩展后写入寄存器 r5，因此 r5 变为 -4（0xFFFF FFFF FFFFFFFC）。如果想得到期望结果 8589934588（0x1FFFFFFFC），可以改用 mul.d 或 mulw.d.w 指令计算，具体写法如下：
``` asm
mul.d 	$r5, $r1, $r2
mulw.d.w 	$r5, $r1, $r2
```
使用 mul.d 指令意味着将 r1 和 r2 按64位数处理，寄存器 r5 被写入的值是乘积结果的完整64位，因此结果为期望的 8589934588（0x0000 0001 FFFF FFFC）。而 mulw.d.w 指令是将寄存器 r1 和 r2 的低32位相乘后，将64位乘积写入寄存器 r5 中，也能得到期望结果。

还可以根据程序功能需要，使用 mulh.w 或 mulh.d 指令获取两个整数乘积的高位部分。

对于除法运算，可以使用 div 和 mod 指令分别获取两个整型数据的商和余数。具体指令如下：
``` asm
div.d 	$r5, $r1, $r2
mod.d 	$r6, $r1, $r2
```
假设此时寄存器 r1 的值为5，寄存器 r2 的值为2。那么这两条指令执行后，寄存器 r5 的值为商2，寄存器 r6 的值为余数1。

【例8】 取两个数的最大值。
``` asm
slt 	$r12, $r4, $r5
maskeqz $r4, $r4, $r12
masknez $r12, $r5, $r12
or 		$r6, $r4, $r12
```
这4条指令实现了类似 C 语言中 `a = (b > c) ? b : c;` 的功能，即取两个数 b、c 中的最大值，并将结果赋值给 a。假设变量 b 存放在寄存器 r4，变量 c 存放在寄存器 r5，变量 a 存放在寄存器 r6。指令 `slt r12, r4, r5` 将 `b < c` 的结果存放在寄存器 r12 中；指令 `maskeqz r4, r4, r12` 和 `masknez r12, r5, r12` 实现当 `b < c` 成立时 r4 为0、r12 为 r5，此时 `or r6, r4, r12` 的结果为 r12，即 `a = c`；当 `b < c` 不成立时，r4 不变、r12 为0，此时 `or r6, r4, r12` 的结果为 r4，即 `a = b`。

【例9】 带立即数的逻辑与运算
``` asm
andi 	$r5, $r2, 3
```
这条指令实现源寄存器 r2 与立即数3的逻辑与运算，并将运算结果写入目的寄存器 r5。假设 r2 的值为 0x7F0，那么 r5 的结果为 0x0。

对于 andi 指令，立即数描述为 ui12，即无符号12位数。当参与运算的立即数超过12位时，需要通过 li 指令加载立即数，再使用 and 指令进行逻辑与运算。

在实际工程中，判断一个地址是否满足特定对齐要求时，使用 andi 指令是一种高效选择。例如，判断一个地址是否满足8字节对齐，只需要判断该地址与立即数 0x7 进行逻辑与运算的结果是否为0；同理，判断一个地址是否满足16字节对齐，只需要判断该地址与立即数 0xF 进行逻辑与运算的结果是否为0。

【例10】 空指令nop的使用
``` asm
nop 		#	andi $r0, $r0, 0
```
nop 指令是 `andi r0, r0, 0` 的别名，实现寄存器 r0 和立即数0的按位逻辑与运算，并将结果写回 r0。龙芯架构参考手册规定，通用寄存器 r0 的值永远为0。可见 nop 指令本身不实现有效计算功能，其作用是占据4字节指令码位置并使 PC 加4，因此称为空指令。但 nop 指令仍有实际意义，例如编译器常用 nop 指令保证内存对齐。在龙芯平台，为提高程序运行效率，通常要求函数起始地址16字节对齐（即可以被16整除）。当编译器发现某个函数中最后一条指令（通常为跳转指令）所在地址不是16字节对齐时，会在最后一条指令后添加1～3条 nop 指令，以确保下一个函数起始地址为16字节对齐。

【例11】 逻辑左移运算
``` asm
sll.w 	$r5, $r1, $r2 	#	LA32,r5 = r1 << r2[4:0]
#	LA64, r5[63:0] = SignExtend(r1[31:0] << r2[4:0])
```
这条指令可以同时运行在 LA32 架构和 LA64 架构上，用于将32位源寄存器 r1 的数据逻辑左移 N 位，并将移位结果（在 LA64 架构上需要符号扩展）写入目的寄存器 r5。这里 N 的取值为源寄存器 r2 的低5位。假设寄存器 r1 的值为205（0xCD），寄存器 r2 的值为0x4，那么这条指令执行后，寄存器 r5 的值应为3280（0xCD0）。

因为 sll.w 的移位量取寄存器 r2 的低5位，对于 `int a = b << 34` 这样的 C 语言运算，34（对应二进制数 0b0010 0010）的低5位为2（对应二进制数 0b00010），计算结果为 `a = b << 2`，相当于对位移量除32取余。同理，对于64位数据（在 LA64 架构中对应 C 语言 long 类型）左移65位的运算，相当于左移1位。

【例12】 带立即数的算术右移运算
``` asm
srai.d 	$r5, $r1, 4
```
在 LA64 架构中，这条指令将源寄存器 r1 的数据算术右移4位，并将移位结果写入目的寄存器 r5。假设寄存器 r1 的值为205（0xCD），算术右移4位后，寄存器 r5 的值为12（0xC）。

在处理器核内，移位指令和乘法指令使用不同功能部件，且移位指令效率通常优于乘法指令。因此，在遇到乘数较小的乘法运算时，例如乘2、乘4、乘8等，可以使用逻辑左移指令替代相应的乘法运算。乘2相当于左移1位，乘4相当于左移2位，乘8相当于左移3位。但当乘法无法用固定移位等价表达时，仍需要使用乘法指令完成相应运算。对于有符号整除运算（即除法运算后余数为0），也可以替换为相应的算术右移指令以提高效率，例如除以2可以替换为算术右移1位，除以4可以替换为算术右移2位。对于无符号整除运算，可以视情况替换为相应的逻辑右移指令。

【例13】 带立即数的循环右移运算
``` asm
rotri.d $r5, $r1, 32
```
在 LA64 架构中，这条指令将源寄存器 r1 的数据循环右移32位，并将移位结果写入目的寄存器 r5。假设寄存器 r1 的值为十六进制 0x11111111EEEEEEEE，循环右移32位后，寄存器 r5 的值应为 0xEEEEEEEE11111111。

【例14】 符号扩展运算
``` asm
ext.w.h 	$r5, $r4
```
这条指令将源寄存器 r4 的低16位[15:0]进行符号扩展后写入目的寄存器 r5。例如，在 LA64 架构中，源寄存器 r4 的值为 0x000000000000FFFA，那么这条指令执行后，寄存器 r5 的值将是 0xFFFFFFFFFFFFFFFA。

符号扩展指令可用于实现高级语言中 byte、short 数据类型向 int 数据类型的转换功能。

【例15】 统计二进制数中连续1的数量
``` asm
cto.d 	$r5, $r4
```
这条指令对源寄存器 r4 中[63:0]数据，从第0位开始向第63位方向统计连续1的个数，并将结果写入目的寄存器 r5。假设 r4 的值为 0x30F，这条指令执行后，寄存器 r5 的值为4。

【例16】 以字为组按字节逆序
``` asm
revb.2w 	$r5, $r1
```
这是一条以字为组按字节逆序的指令。假设源寄存器 r1 的值为 0xEE00FF11 CC22DD33，那么这条指令执行后，目的寄存器 r5 的值为 0x11FF00EE33DD22CC。

按字节逆序相关指令在进行尾端转换时非常有用，例如大尾端转换为小尾端，或小尾端转换为大尾端。一个32位整型数据的尾端转换，使用 C 语言可实现为：
``` c
int reverse_dst = (src << 24) | ((src & 0xff00) << 8) | ((src >> 8) & 0xff00) | (src >> 24);
```
如果 src 的值为 0x11223344，那么最终 reverse_dst 的值为 0x44332211。对应的 LoongArch 汇编指令为：
``` asm
revb.2w 	$r7, $r4
slli.w 		$r7, $r7, 0
```
这里假设变量 src 存放在寄存器 r4，变量 reverse_dst 存放在寄存器 r7，那么 revb.2w 指令的作用是将寄存器高32位、低32位分别以字节为单位逆序，并将逆序结果存入 r7。因为此处实现的是32位整型数据的尾端转换，所以增加 slli.w 指令实现32位数到64位寄存器的有符号扩展。

【例17】 从内存读数据
``` asm
ld.w 	$r12, $r13, 0x7f
```

这条指令从指定内存地址加载一个32位数据到目的寄存器 r12 中。在 LA64 架构上，加载后的数据需要进行符号扩展，然后写入目的寄存器 r12。这里指定内存地址的计算方式为源寄存器 r13 与立即数 0x7f 相加。假设 r13 的值为 0x12000000，那么指定内存地址即为 0x12000007f。

在编译器内部，通常会将数组下标0所在地址、类对象所在地址、字符串首字符所在地址、堆栈指针寄存器 SP 等作为基址，然后通过偏移量索引其他数据。例如，对于数组 `int a[20]`，基址是 `&a[0]`。当要加载数组中某一项时，偏移值为数组类型宽度与下标的乘积。加载 `a[3]` 的值时，地址计算方式为 `base(&a[0]) + sizeof(int) * 3`。

当地址偏移量超出 si12 所能表示的范围时，需要先将偏移量加载到寄存器，然后使用基址加寄存器偏移的指令。例如偏移量为 0x7ff4 时，此值超出了12位，具体指令如下：
``` asm
li.w 	$r14, 0x7ff4	#	加载立即数0x7ff4到寄存器r14
ldx.w 	$r12, $r13, $r14 	#	从内存地址(r13+r14)加载一个字(32位)到寄存器r12
```
【例18】 写数据到内存
``` asm
st.b 	$r12, $r13, 0x7f
```
这条指令将寄存器 r12 的低8位[7:0]数据写到指定内存地址。这里指定内存地址的计算方式为源寄存器 r13 + 0x7f。

【例19】 满足内存地址自然对齐的32位/64位数据访存
``` asm
ldptr.w 	$r12, $r13, 0x7ff4
```
这条指令同样用于从指定内存地址加载一个32位数到寄存器 r12 中。在 LA64 架构上，加载后的数据需要进行符号扩展，然后写入目的寄存器 r12。但这条指令的内存地址计算方式为源寄存器 r13 + (0x7ff4 << 2)，即需要将偏移量逻辑左移2位。

表3-5中，指令名前缀带 ptr 标识的访存指令（如 ldptr.w、ldptr.d）也属于基址加立即数偏移（base + offset）类型，但立即数所能表达的范围更大。当访存地址低两位为0时（可理解为满足内存地址自然对齐），相较于 ld/st 指令，可以使用此类指令实现偏移范围为16位 [-32768, 32767] 的地址访问。例如，偏移地址 0x7ff4 超过12位，但在16位范围内，而且低两位都为0，因此可以使用 ldptr.w 指令实现加载。与【例17】相比，这里减少了一条加载立即数 0x7ff4 的指令，性能更好。

【例20】 预取数据
``` asm
preld 	8, $r6, 0
```
这条指令从地址 r6 + 0 的内存位置读取一个 Cache 行（龙芯3A5000系列芯片中一个 Cache 行为64字节）的数据到 Cache 中。hint = 8 表示预取的数据接下来会有写（Store）处理。

合理使用预取指令可以减少程序运行中 Cache Miss（缓存未命中）带来的延迟，提升程序效率。程序运行时必然伴随处理器和存储器之间的数据交互，这种交互通过访存指令完成。当处理器执行到一条访存指令时，如果待访问地址的数据不在缓存中，即发生 Cache Miss，处理器可能需要等待上百个时钟周期，直到访存部件从内存中取数据到缓存，从而影响程序执行效率。数据预取指令的目的，是在下一个访存指令到来之前，先将数据从内存调入 Cache，从而避免 Cache Miss 带来的延迟。

【例21】 带边界检查的存储操作
``` asm
addi.w 	$r13, $r0, 1(0x1) 	#	加载立即数1到寄存器r13
stle.w 	$r13, $r12, $r14 	# 	如果(r12 <= r14)成立，将寄存器r13的值写入r12所指内存
#	否则写失败，触发边界检查例外
```
当指令 `stle.w r13, r12, r14` 被执行时，处理器首先判断寄存器 r12 中的地址值是否小于或等于（le）寄存器 r14 中存放的地址值。根据程序逻辑，可以让寄存器 r14 存放数组边界值（&array[99]）。如果寄存器 r12 中存放的是 &array[101]，那么小于或等于条件不成立，stle.w 指令执行时会触发边界检查例外，写操作也不会执行，从而避免程序继续运行并将错误传导到其他位置，增加调试定位难度。开发者在编写程序时，可以专门建立一个线程用于接收此类例外（SIGSEGV），并及时处理或向终端反馈易读信息。事实上，一些高级语言编译器（例如 Java 虚拟机）内部动态防御功能的异常处理机制，其实现原理也与此类似。

【例22】 数据栅障的使用方法
``` asm
#	写进程
st.d 	val, data 	#	写数据到共享区域data
st.d 	1, tag 		#	写数据到共享区域tag
```
一个程序的写进程使用两条写内存指令对共享存储区域（分为数据区 data 和标识区 tag）进行写数据处理。第一条指令负责将数据写到数据区 data，第二条指令负责将数据1写到标识区 tag，用于通知其他进程该数据区有新数据写入。相应地，读进程需要先读取标识区 tag，并判断其值为1后才能读取数据。
``` asm
# 	读进程
ld.d 	reg, tag 	# 	读标识区tag
beqz 	reg, L 		# 	标识如果为0，则跳转到L执行nop
ld.d 	val, data 	#  	否则证明标识区为1，执行读数据区data
L:	nop
```
这段程序运行在弱一致性模型的处理器上会存在隐患。由于乱序执行技术的存在，写进程中的两条没有数据相关的写指令 `st.d val, data` 和 `st.d 1, tag` 可能被乱序执行，即第二条写指令被提前到第一条写指令之前完成，相当于在尚未写完数据区时就发出了数据已经写完的通知。在这种情况下，读进程可能先读到标识区的值为1，导致条件成立并执行对数据区 data 的读取，而此时读到的数据仍是之前的旧数据。

【例23】 使用LL-SC实现a=a+1的原子操作
``` text
1:                     # label 1
ll.w   r4, &a      # 加载内存数据(a)到寄存器r4
addi.w r6, r4, 1   # 加1
sc.w   r6, &a      # 结果写回内存
beqz   r6, 1b      # 如果写回失败（r6为0）则跳转到label 1，重复读-修改-写
```
这4条指令构成一个循环。当 sc.w 写回内存失败后，程序会继续向前跳转并执行 ll.w、addi.w、sc.w 指令序列。

【例24】 使用amadd指令实现一个整型a=a+1的原子操作
``` text
li.w 	$r2, 1 		#	加载立即数1 
li.w 	$r4, &a 	#	加载变量a的地址 
amadd.w $r0, $r2, $r4 	#	a = a + 1并写回a的地址。旧值不做保存故使用寄存器r0 
```
这里变量 a 所在地址保存在寄存器 r4 中。立即数1保存在寄存器 r2 中。因为不需要保留旧值，所以 rd 寄存器使用 r0（其值永远为0）。指令执行后，寄存器 r2 的值与寄存器 r4 所指地址中的旧值相加，并写回寄存器 r4 所指地址，即变量 a 的值变为 a + 1。

需要注意的是，AMO 仅支持32位和64位数据的简单算术和逻辑原子运算。对于8位、16位数据的原子运算，或需要实现更复杂的原子操作时，只能使用 LL-SC 原子访存指令对实现相应功能。

【例26】 用汇编指令实现下面C语言中的程序流控制
``` c
if(a == 0)	b++;	//	如果整型变量a等于0，则整型变量b加1
else b--;  			//	否则b减1
```
此功能对应的LoongArch汇编指令如下：
``` asm
beqz 	$r4, 8
addi.w 	$r5, $r5, -1 	#	b--
b 		4
addi.w 	$r5, $r5, 1 	#	b++
nop
```
这里假设变量 a 和 b 分别存放在寄存器 r4 和 r5 中。第一条指令 `beqz r4, 8` 用于判断变量 a 是否等于0。如果 a 等于0，则跳转到指令 `addi.w r5, r5, 1` 完成 b++ 操作；否则不跳转，继续执行指令 `addi.w r5, r5, -1` 完成 b-- 操作，然后通过指令 `b 4` 无条件跳过 b++ 操作。

【例27】 用汇编指令实现C语言中的函数调用和函数返回
``` c
int add(int a,int b){	//	实现两个数的加法运算
	return a + b;
}
int main(){
	add(1,2); 			//	调用函数add，实现1+2
}
```
此功能对应的LoongArch汇编指令如下：
``` asm
add:
...
add.w 	$r4, $r4, $r5 	#	a+b
jirl 	$r0, $r1, 0 	#	函数返回，寄存器r1存放函数的返回地址
main:
...
bl 		add 			#	调用函数add
...
jirl 	$r0, $r1, 0 	#	main函数返回，寄存器r1存放函数的返回地址
```
函数 main 中的 bl 指令在跳转到函数 add 之前，会将其下一条指令地址（PC + 4）写入寄存器 r1。函数 add 中的最后一条 jirl 指令跳转目标地址为 r1（r1 + 0），意味着跳转到其被调用处（即函数 main 中 bl 指令的下一条指令位置）。jirl 跳转的同时会将其下一条指令地址写入寄存器 rd。这里 rd 使用0号寄存器（r0 值永远为0），表示此时 jirl 是一条普通的非调用间接跳转指令。

:::{tip}
这里指令 `bl add` 也是一条宏指令（即由编译器识别并最终翻译成真实汇编指令）。此处 add 为标签（Label），在编译器链接阶段会被替换为具体目标地址。
:::

【例28】 通过系统调用指令实现用户进程退出功能

内核提供的进程退出功能接口函数为 `sys_exit(int error_code)`。LoongArch ABI 规定此函数的系统调用号为93，使用寄存器 r11 传递系统调用号，使用 r4～r10 传递系统调用参数。实现 sys_exit 系统调用的指令如下：

``` asm
li.w 	$r11, 93 	#	加载系统调用号93到寄存器r11
li.w 	$r4, 0 		#	将错误码值0作为第一个参数，加载到寄存器r4
syscall	0 			#	系统调用，程序陷入内核态
```
处理器执行指令 `syscall 0` 后，系统会进入内核态并执行内核中实现的 sys_exit() 函数，从而完成退出当前用户进程的功能。从用户角度来看，其功能相当于执行 libc 库中的 exit(0) 函数。

【例31】 获取当前处理器是否支持非对齐访问
``` asm
li.w 	$r4, 1 		#	加载配置字号1到寄存器r4
```

【例32】 使用 IEEE 802.3 多项式对一个 byte 数组内的所有数据进行 CRC
``` asm
loop:
ld.d 		tmp, buf, 0 	#	从内存地址(buf+0)加载1字节到寄存器tmp
crc.w.b.w 	crc, tmp, crc 	#	对寄存器crc与寄存器tmp进行CRC，将结果写回寄存器crc
addi.d 		buf, buf, 1 	#	地址加1
addi.d 		len, len, -1 	#	数组长度减1
blt 		r0, len, loop 	#	如果数组没有完成，跳到loop继续执行
```
这里使用一个循环，对数组内的每个字节逐一进行 CRC 累积运算。其中 tmp、buf、crc、len 是寄存器 r1～r31 中任意寄存器的别名。寄存器 buf 的初始值为数组起始地址；寄存器 len 表示数组长度；寄存器 crc 用于存放累积 CRC 校验和，其初始值可设为0。这里通过一个循环完成对数组 buf 中全部字节的32位累积 CRC 校验和计算。其中，指令 `crc.w.b.w crc, tmp, crc` 使用 IEEE 802.3 多项式，将寄存器 crc 中32位累积 CRC 校验和与寄存器 tmp[7:0] 根据 CRC32 校验和生成算法计算出新的32位 CRC 校验和，并将结果符号扩展后写回寄存器 crc。
