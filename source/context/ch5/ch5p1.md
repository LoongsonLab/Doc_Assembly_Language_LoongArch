#	数据类型、数据对齐和字节序列

了解一个架构的ABI，首先需要明确该架构对高级语言（通常为C语言）中基本数据类型的内存大小、内存对齐方式和字节序的约定。这样，在编写汇编语言时才能根据不同数据类型选择合适指令，同时也能避免高级语言程序在不同架构间移植时出现错误。

##	数据类型

在LA32架构下，通用整数寄存器宽度为32位，因此内存加载和参与运算的数据大小可以是字节（8位）、半字（16位）、字（32位），分别对应C/C++语言中的`bool`/`char`、`short`、`int`/`long`等数据类型。在LA64架构下，通用整数寄存器宽度为64位，因此内存加载和参与运算的数据大小可以是字节（8位）、半字（16位）、字（32位）、双字（64位），分别对应C/C++语言中的`bool`/`char`、`short`、`int`、`long`等数据类型。更具体的C/C++语言数据类型宽度及其对齐方式如表5-1所示。

需要注意的是，数据类型`long`在LA32架构下大小为4字节，在LA64架构下大小为8字节。数据类型`__int128`和`long double`的大小均为16字节，意味着对这两种数据类型进行数据加载或计算时，在LA64架构下需要2个寄存器，在LA32架构下需要4个寄存器。

##	数据对齐

为了简化处理器与内存系统之间的硬件设计，许多计算机系统会限制访存操作的地址，要求被访问地址必须是其数据类型大小的整数倍，这称为自然对齐。也就是说，从内存中读取或写入一个半字（2字节）数据时，访存地址必须是2的倍数；读取或写入一个字（4字节）时，访存地址必须是4的倍数；读取或写入一个双字（8字节）时，访存地址必须是8的倍数。更具体的数据类型及其对应对齐方式如表5-1所示。下面列举几个对齐访问和非对齐访问的例子：
``` asm
//	假设寄存器r5的地址值为0x12000000
ld.w 	$r4, $r5, 0x3 		//	0x12000003不能被4整除，为非对齐访问
ld.w 	$r4, $r5, 0x8 		//	0x12000008能被4整除，为对齐访问
ld.d 	$r4, $r5, 0x5 		//	0x12000005不能被8整除，为非对齐访问
```
LoongArch支持由硬件处理非对齐内存数据访问。也就是说，虽然上面示例中存在非对齐访问，但处理器仍能正常工作并得到正确结果，不会抛出非对齐异常。不过，为获得更优性能，建议程序员尽量保证数据对齐，因为硬件处理非对齐数据访问的效率通常低于处理对齐访问。

使用C语言编写程序时，编译器会自动处理对齐问题，使每个变量在内存中的起始地址满足自然对齐要求。例如，对于如下顺序定义的C语言变量：
``` c
char cVar;
int iVar;
short sVar;
long lVar;
```
编译器对此处理后在内存中的存放次序和地址如表5-2所示。

从表5-2可以看出，虽然变量`cVar`的数据类型为`char`，仅占1字节，却在内存中占据了4字节地址空间，目的是保证下一个整型变量`iVar`的地址（0x120008074）满足4字节对齐。变量`cVar`占据从内存起始地址0x120008070开始的4字节中的低8位，高24位未使用，也称为填充（Padding）位。变量`sVar`的数据类型虽然为2字节，却需要占用8字节地址空间，目的同样是保证下一个变量`lVar`的地址（0x120008080）满足8字节对齐。

对于C语言结构体中的变量，其内存布局也遵循自然对齐原则。

## 	字节序列

字节序定义了以字节为单位的半字、字、双字在内存中如何排列。常见字节序包括大端序（Big Endian）和小端序（Little Endian）两种。假设C语言中一个`int`类型变量x的十六进制值为0x12345678，其在内存中按照大端序和小端序存储的示意图如图5-1所示。

```{image} ../../img/ch5/pic_5_1.png
:alt: 数据0x12345678的大尾端和小尾端的存储方式
:class: bg-primary
:scale: 80 %
:align: center
```

从图5-1可以看出，对于多字节数据，大端序的存储方式是从内存低地址开始，依次存放数据的高位到低位；小端序的存储方式与大端序相反，是从内存低地址开始，依次存放数据的低位到高位。不同架构采用的字节序不同，例如x86和LoongArch采用小端序存储，而ARM、MIPS的字节序存储方式是可配置的。

多数情况下，机器使用的字节序对应用程序不可见，也无需特别关注。因为在同一架构上，内存数据的读和写采用相同字节序。但在某些特殊场景中，例如跨机器网络传输数据时，如果两端机器采用的字节序不同，且接收端没有对发送过来的基本类型数据进行字节序转换，就可能出现读取数据错误。这种情况下需要了解字节序，并采取相应转换处理。验证当前机器使用哪种字节序比较简单，例如可先向某个内存地址写入一个`short`或`int`类型数据，再从该内存起始地址读出1字节数值；如果该数值为写入数据的低8位，则为小端序，否则为大端序。
