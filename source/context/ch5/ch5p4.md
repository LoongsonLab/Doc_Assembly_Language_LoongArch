#	函数栈布局

LoongArch ABI规定，函数栈向下增长（朝向更低地址），栈指针在函数入口处应对齐到16字节边界，且在栈上传递的第一个实参位于函数入口栈指针偏移量为0的位置，后续参数存储在更高地址中。函数栈在程序运行时动态分配，用于保存函数调用时需要维护的信息，包括函数返回地址、参数、临时变量和栈位置等。一个典型函数栈如图5-14所示。

在图5-14中，GPR表示通用寄存器，即LoongArch中的32个整数寄存器。GPR[sp]代表通用寄存器sp。每次函数开始时，sp都会在预先指定的内存区域中由高地址向低地址移动n字节，以实现函数栈空间分配。这里要求n必须是16的倍数。典型的函数栈分配指令如下：
``` asm
addi.d 	$sp, $sp, -48
```
这条加法指令相当于C语言表达式`sp = sp - 48`，即申请一个48字节的栈空间。函数栈空间分配指令多出现在函数开头；函数返回时，再通过将sp指针向上移动48字节释放栈空间，指令如下：
``` asm
addi.d 	$sp, $sp, 48
```
有了函数栈空间后，当函数内部寄存器不够使用，或发生函数调用时，就可以将一些数据存储到栈空间（通常称为进栈），需要时再从栈空间加载到寄存器（通常称为出栈）。

栈空间以进程为单位分配。进程是系统进行资源分配和调度的基本单位。系统会在进程启动时指定一个固定大小的栈空间，用于存储该进程的函数参数和局部变量。sp的初始值指向这个固定大小栈的栈底。该进程中的每一次函数调用，都会通过移动sp指针在此空间中划分出一块作为函数栈的区域，sp指向栈顶。函数栈又称为栈帧（Stack Frame），通用寄存器fp（r22）指向当前函数栈的栈底。fp也称为帧指针（Frame Pointer）。sp和fp共同限定每个函数的栈边界，如图5-15所示。

在图5-15中，每个函数栈内部的fp都指向调用者函数的栈顶。当需要回溯函数调用关系或进行动态堆栈管理时，可以通过当前函数中的sp和fp得到上一个函数的sp和fp，并以此类推直到第一个函数。
