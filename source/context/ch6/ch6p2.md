#	进程虚拟地址空间和页大小

龙芯架构参考手册描述，应用软件能够访问的内存物理地址空间范围是0~2<sup>PALEN</sup>-1。在LA32架构下，PALEN理论上是一个不大于32的正整数，通常建议为32；在LA64架构下，PALEN理论上是一个不大于64的正整数，其具体值由实现决定，通常PALEN在[40,48]范围内。应用软件可以通过执行CPUCFG指令读取0x1号配置字的PALEN域来确定PALEN具体值。龙芯3A5000处理器（LA64架构）上PALEN的值为48，即支持的内存物理地址空间范围是0~2<sup>48</sup>-1。当程序中访存指令的地址超出上述范围时，将触发异常。

如今，除对处理速度和内存大小要求较苛刻的实时操作系统、嵌入式系统可能直接使用内存物理地址外，较复杂的操作系统通常不会让程序直接访问物理内存，而是使用虚拟地址空间。存储管理部件（Memory Management Unit，MMU）负责将虚拟地址转换为物理地址，并对软件程序隐藏物理地址概念，从而使进程能够安全且并行地运行在系统物理地址空间中。每个进程都有独立的虚拟地址空间，这段虚拟地址空间会被划分为几个不同区域进行管理。图6-4展示了一个典型C语言程序运行时的用户态虚拟内存布局。

一个典型进程至少包括代码段、数据段、栈空间、共享库和堆区等区域，动态链接进程还可以动态创建更多段空间。不同段空间的数据占据一个或多个内存页，并具有不同访问权限。例如，一般而言，代码段所在内存页具有读和执行权限，而数据段通常可读可写。在LoongArch架构下，程序被加载到虚拟内存的起始地址通常为0x1C0000000，0x000000000~0x1C0000000范围内的地址为预留地址。

内存地址空间按照页（Page）组织，页是Linux系统下内存管理的基本单位。不同系统的页大小可能不同，这取决于处理器、MMU和系统配置。可以通过如下命令查看当前系统页大小：
``` shell
$ getconf PAGE_SIZE
4096
```
`getconf`命令显示当前系统页大小为4096字节，即4KB。当程序被加载到内存时，小于4KB的段会被加载到一个内存页；大于4KB的段则会被加载到两个或多个连续内存页。
