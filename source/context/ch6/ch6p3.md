#	可执行文件与进程虚拟地址空间的映射

系统启动一个进程时，首先要将可执行文件中的必要数据加载到内存，然后程序才能运行。但并不是所有数据都会被加载。对于一个典型可执行文件，只有程序头中记录的类型为LOAD的段需要被加载到内存，其他段不需要加载到内存，仅用于辅助判断如何加载。一个典型可执行文件数据被加载到虚拟内存的情况如图6-5所示。

:scale: 80 %

图6-5中，仅段1和段2需要被加载到内存，分别放在VMA2和VMA1。VMA的全称为Virtual Memory Area，即虚拟内存区域。一个VMA可以占用一个页或多个页，其大小是页大小的整数倍。通常不同VMA具有不同权限，例如VMA1存放代码，权限为只读且可执行；VMA2存放数据，权限为可读写。从图6-5可以看出，可执行文件加载（映射）到内存时，ELF文件头和调试信息（`.debug_info`、`.debug_str`段等）不需要加载，真正需要加载的是部分段（如`.text`、`.bss`、`.data`段等），也就是段类型为LOAD的段。

实际开发中，还可以通过`/proc/pid/maps`节点查看某个进程的虚拟地址空间布局，其中pid为待查看进程号。例如，要查看系统进程号为30828的虚拟地址空间布局，可以使用命令`cat /proc/30828/maps`，显示信息如下：
``` shell
$ cat /proc/30828/maps
120000000-120004000 r-xp 00000000 08:00 100794371    /home/v/c-test/a.out
120004000-12000c000 rwxp 00004000 08:00 100794371    /home/v/c-test/a.out
fff718c000-fff72dc000 r-xp 00000000 08:11 3539724    /usr/lib/loongarch64-linux-gnu/libc-2.28.so
fff72dc000-fff72f0000 r-xp 0014c000 08:11 3539724    /usr/lib/loongarch64-linux-gnu/libc-2.28.so
fff72f0000-fff72f4000 rwxp 00160000 08:11 3539724    /usr/lib/loongarch64-linux-gnu/libc-2.28.so
fff72f4000-fff72f8000 rwxp 00000000 00:00 0
fff7318000-fff7338000 r-xp 00000000 08:11 3539080    /usr/lib/loongarch64-linux-gnu/ld-2.28.so
fff7338000-fff733c000 r-xp 0001c000 08:11 3539080    /usr/lib/loongarch64-linux-gnu/ld-2.28.so
fff733c000-fff7340000 rwxp 00020000 08:11 3539080    /usr/lib/loongarch64-linux-gnu/ld-2.28.so
fffb8ac000-fffb8d0000 rw-p 00000000 00:00 0                     [stack]
ffff07c000-ffff080000 r--p 00000000 00:00 0                     [vvar]
ffff080000-ffff084000 r-xp 00000000 00:00 0                     [vdso]
```
第一列为VMA地址范围；第二列为VMA权限，可以是可读（r）、可写（w）、可执行（x）、私有（p）、可共享（s）。例如，`r-xp`表示此段虚拟地址空间数据可读、可执行且为私有映射，但不可写；第三列为VMA对应Segment在映射文件中的偏移；第四列表示映像文件所在设备的主设备号和次设备号；第五列表示映像文件的节点号；最后一列是映像文件路径。

这里显示该进程共占用12个VMA。进程使用的起始地址为0x12000000。前两个VMA（12000000~120004000、120004000~12000c000）映射到ELF文件的两个Segment，分别用于存放当前程序的代码段（权限为`r-xp`）和数据段（权限为`rwxp`）。程序使用的动态库`libc-2.28.so`被映射到接下来的3个VMA。0x12000c000~0xfff718c000范围内的地址没有被映射，这段区域是堆区（Heap），程序可通过类似`malloc`的函数申请使用。`ld-2.28.so`是Linux下的动态链接器，负责`libc-2.28.so`中与绝对地址相关的代码和数据的动态重定位过程，它占据了3个VMA。地址fffb8ac000~fffb8d0000为进程栈空间。最后2个VMA（ffff07c000~ffff080000、ffff080000~ffff084000）分别被vvar和vdso模块占用。这两个模块是内核映射出的区域，用于让程序绕过系统调用`syscall`，直接通过某些接口与内核快速通信。例如，在大多数体系架构中，`gettimeofday`都可通过vdso直接实现以提高运行速度。
