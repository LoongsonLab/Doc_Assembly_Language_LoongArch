#	汇编语言的使用场景

许多使用高级语言编程的开发者，在从业之初甚至工作多年后，都会产生这样的疑问：既然当前大多数应用程序都使用高级语言编写，学习汇编语言还有什么用处？下面列举几个典型使用场景。

##	场景1——快速定位问题和分析问题

先看一个较简单的例子：浮点数例外。多数程序开发者在工作中都可能遇到异常信号SIGFPE。当程序执行除法运算时，如果除数为0，系统就会发送SIGFPE信号（中文环境中可能显示为“浮点数例外”）。触发该异常的C语言代码如下：
``` c
int test(int a,int b){
	return a/b;
}
```
调用函数`test`时，如果故意将参数b传入0，就会收到“浮点数例外”。使用调试工具GDB（GNU Debugger，Linux系统下的调试工具）在龙芯平台上调试这段代码时，可以获取如下信息：
``` shell
Program received signal SIGFPE, Arithmetic exception.
0x00000001200006ec in test ()
(gdb) bt
#0  0x00000001200006ec in test ()
#1  0x0000000120000734 in main ()
```
这里GDB已经列出了函数调用栈，即函数`main`调用了函数`test`，并且在执行函数`test`中地址为0x00000001200006ec处的指令时触发了SIGFPE异常。那么，0x00000001200006ec处的指令是什么？可以使用GDB进一步确认。
``` shell
(gdb) x/5i $pc-12
0x1200006e0 <test+40>: ld.w    $r12,$r22,-24(0xfe8)
0x1200006e4 <test+44>: div.w   $r14,$r13,$r12
0x1200006e8 <test+48>: bne     $r12,$r0,8(0x8) # 0x1200006f0 <test+56>
=> 0x1200006ec <test+52>: break  0x7
0x1200006f0 <test+56>:  move   $r12,$r14
```
其中，`=>`标识当前PC（Program Counter，用来存放当前待执行指令的地址）位置，即程序当前停止的位置。上面的汇编指令`div.w $r14,$r13,$r12`为除法指令，表示用寄存器$r13除以$r12，并将结果写入$r14。汇编指令`bne $r12,$r0,8(0x8) #0x1200006f0`是条件跳转指令，用于判断除数$r12是否等于0（寄存器$r0为特殊寄存器，其值恒为0）。如果二者不相等，则跳转到地址0x1200006f0处继续执行；否则不跳转，继续执行下一条汇编指令`break 0x7`。`break`指令会无条件触发断点例外，其参数0x7对应SIGFPE。至此可以判断，当前程序异常是由除法指令中的除数为0引起的，对应的C语言代码为`return a/b;`，其中b为0。

大型软件的异常定位通常也遵循类似思路。许多大型软件会内置较完整的异常处理机制，在异常发生时自动收集异常原因、异常进程、异常位置、栈回溯等信息，例如Java虚拟机中的异常捕获机制、Android系统中的tombstone机制。尽管如此，仍可能遇到异常处理机制无法捕获的问题。此时，掌握调试工具的使用方法和必要的汇编语言知识就十分重要。

关于GDB工具的使用，后续章节还会进行更详细的介绍。

##	场景2——性能分析和优化

了解计算机体系架构和汇编语言，有助于深入分析软件性能瓶颈。虽然编译器已经承担了大量性能优化工作，例如C/C++编译器GCC（GNU Compiler Collection，GNU编译器套件）在编译时使用`-O3`通常比使用`-O1`能够获得更进一步的优化；Java虚拟机也支持根据函数大小和函数调用频率动态调整优化策略。但是在某些特定场景中，这些优化仍可能不足，例如游戏引擎、音视频编解码等领域经常涉及与算法相关的大规模数学运算。此时，如果掌握汇编语言，就可以进一步进行面向特定处理器的优化。多数处理器都实现了单指令流多数据流（Single-Instruction stream Multiple-Data stream，SIMD）功能的汇编指令，也称为向量指令，它可以通过一条指令同时操作多组数据。龙芯架构LoongArch中也实现了SIMD，包括向量扩展（Loongson SIMD Extension，LSX）和高级向量扩展（Loongson Advanced SIMD Extension，LASX），其中LSX的向量位宽为128位，LASX的向量位宽为256位。

下面以使用龙芯LASX进行程序优化为例。以下C语言代码实现a数组与b数组中对应元素相加，并将结果写入c数组。这里假设数组元素类型为整型`int`（32位），循环长度为10000。
``` c
for(int i = 0;i < 10000;i++)
	c[i] = a[i] + b[i];
```
使用GCC编译后，生成的、最终可供CPU执行的指令如下：
``` asm
L:
ld.w 	t1, a1, 0 	#	加载数组a[i]值到寄存器t1
add.w	t3, t1, t2	#	实现a[i]+b[i]，将结果存入寄存器t3
st.w	t3, t4, 0 	#	t3数据写回c[i]
addi.d 	a1,	a1, 4 	#	数组a[]累加4，即指向a[i+1]
addi.d 	a2,	a2, 4 	#	数组b[]累加4
addi.d 	t4,	t4, 4 	# 	数组c[]累加4
bne 	a5, a6, L 	#	判断若for()没有结束，跳转到L，继续执行
```
上面这段指令实现了循环操作`c[i] = a[i] + b[i]`，相关指令格式将在后续章节详细介绍。可以看出，要实现两个长度为10000的整型数组加法运算，CPU需要循环执行10000次，每次循环执行8条指令，因此完成整个功能需要执行80000条指令。

同样的功能，用龙芯LASX指令实现如下：
``` asm
L:
xvld 	x1, a1, 0 	#	加载数组a[]中的8组整数值到向量寄存器x1
xvld 	x2, a2, 0 	#	加载数组b[]中的8组整数值到向量寄存器x2
xvadd.w x3, x1, x2	#	a[i...i+8] + b[i...i+8],结果存入向量寄存器x3
xvst 	x3, t4, 0 	#	把x3数据写回数组c[i...i+8]
addi.d 	a1,	a1, 32 	#	数组a[]累加32，即指向a[i+9]
addi.d 	a2,	a2, 32 	#	数组b[]累加32
addi.d 	t4,	t4, 32 	# 	数组c[]累加32
bne 	a5, a6, L 	#	判断若for()没有结束，跳转到L，继续执行
```
龙芯LASX指令为256位宽（即向量寄存器长度为256位），因此循环一次可以完成8组整型值（8×32位）的加法运算。每次循环同样执行8条指令，但总循环次数仅为1250次（10000/8），完成整个功能只需执行10000条指令（1250×8）。理论上，其执行效率可达到GCC编译器生成的普通指令的8倍。本书第10章将专门介绍与指令架构相关的性能优化基本思路和方法。

##	场景3——完成高级语言无法实现的功能

在一些基础软件的源代码中，例如数据库、GCC编译器、OpenJDK等，经常可以看到汇编语言的使用。作为应用软件的支撑或工具，这类软件在运行逻辑上比普通应用软件更接近CPU，因此更容易涉及与计算机体系架构相关的功能需求。例如，GCC编译器负责将C/C++语言翻译成与计算机体系架构相关的汇编语言；Java开发者熟知的OpenJDK负责Java语言到机器指令的动态翻译和执行。因此，相关软件从业者不仅需要熟悉某种高级语言，还需要理解特定处理器支持的汇编语言。

例如，在C语言中如何获取程序运行时的当前PC值？不同架构有不同实现方式，在龙芯平台上可以通过如下内嵌汇编实现。
``` c
static long* get_PC(void){
	unsigned long* val;
	__asm__volatile("move %0, $r1":"=r"(val));
	return val;
}
```
这里`__asm__`是内嵌汇编指令，用于实现汇编语言和C语言的混合编程，后续章节将专门介绍其语法规范。这里重点关注核心汇编指令`move %0, $r1`。在龙芯架构寄存器使用约定中，寄存器$r1存放函数返回地址，`%0`代表变量val，因此`move %0, $r1`完成了将当前函数的返回地址存入变量val的操作。当前函数的返回地址就是调用该函数时的PC，因此可以通过调用这个函数获取当前位置的PC。

汇编语言也是编写嵌入式设备程序的重要工具。与通用计算机处理器相比，嵌入式设备（如电话、打印机、门禁设备等）的典型特征是内存容量有限，这要求其运行的程序尽量短小。如果使用高级语言编写，经过编译器翻译后的机器指令可能包含一定冗余，例如函数调用开销、动态库加载开销（即使程序只使用某个动态库中的少数函数）等。如果直接使用汇编语言进行有针对性的编写，通常可以进一步减少内存占用，因此汇编语言特别适合某些嵌入式程序。后续章节将专门介绍如何编写一个脱离libc库的程序示例。
